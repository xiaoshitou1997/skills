# Next.js 条款

项目实际使用 Next.js 时并读本文件；通用条款见 [frontend-guide.md](frontend-guide.md)。与项目已确立基线冲突时以项目为准。本文按项目实际使用的 App Router / Pages Router 与 Next.js 版本应用，不向其他版本强加不兼容条款。

## 渲染模式与交付约束

- 先确认项目的渲染模式：静态导出（`output: 'export'`）或服务端渲染（SSR/ISR）。两种模式的交付方式不同——静态导出走内置的静态站点交付模板（`CONTAINER_PORT=80`）；SSR 需要项目自备 `Dockerfile.delivery`（Node 运行时），不能混用。
- 渲染模式是项目级决定，不在单次改动中静默切换；确需切换时按交付契约确认镜像与部署影响后再动。
- 页面级选择渲染策略（动态参数、缓存与再验证）时同时确认其对构建产物与交付模式的含义。

## 路由与约定文件

- 路由目录只放路由层文件（`page`/`route`/`layout`/`loading`/`error` 等约定文件）；页面业务拆到同目录 colocated 组件与 hooks，不把整页逻辑堆进 `page` 文件。
- 共享布局（`layout`）承载导航与全局壳，不放页面级业务状态；`error`/`loading` 按路由段就近覆盖，保证局部失败不拖垮整页。
- 动态路由参数与查询参数的解析收敛在一处（页面入口），向下游传类型化参数。

## 服务端/客户端组件边界

- 默认服务端组件；仅当需要状态、事件、浏览器 API 或第三方客户端库时加客户端标注，且标注尽量靠近叶子组件，不在分支根部整棵标客户端。
- 跨边界 props 必须可序列化；不把服务端才可用的对象（连接、密钥、文件句柄）传给客户端组件。
- 客户端组件不 import 仅服务端的模块（服务端密钥读写、数据库访问层）；构建期这类越界会失败，不绕过报错硬改打包配置。

## 数据获取

- 服务端取数在服务端组件/路由处理器内完成，直接调用服务层或后端契约；客户端补充取数走统一服务层封装，不在组件散落请求。
- 使用缓存与再验证语义时显式声明意图（刷新时机、缓存键），不用默认缓存行为代替判断；涉及用户敏感数据的请求不进共享缓存。
- 表单提交与变更操作走服务端动作或统一 API 层，带错误与加载态；成功后的重验证范围取最小受影响集合。

## Route Handlers（BFF 定位）

- Route Handler 只做协议转换、鉴权透传与聚合，不承载业务规则——业务规则在后端服务；发现规则下沉到前端时停下，回后端补契约。
- Handler 内不硬编码上游地址与密钥，一律走服务端环境变量；对外响应不透传内部错误栈。

## 资源与元数据基线

- 图片用框架图片组件或约定的静态资源通道（自动尺寸、懒加载、格式优化），不手写未约束的 `<img>` 引入大图。
- 字体走框架字体加载方案，避免布局抖动；每页元数据（标题、描述）按路由声明，不整站一个标题。

## 环境变量

- `NEXT_PUBLIC_*` 只放无环境差异的公开常量（会被打进产物）；服务端专用变量不加公开前缀，且只在服务端代码读取。
- 分环境 API 地址与开关走运行时注入或相对路径，不靠多套构建产物区分环境（与交付侧「同一产物跨环境」约束一致）。

本文只覆盖 Next.js 工程条款；渲染模式对应的镜像构建与部署契约归 mv-build-image-builder 与 mv-delivery-container-deploy，本地 dev server 调试归 mv-impl-local-debug。
