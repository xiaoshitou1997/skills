# 前端工程规范（框架中立）

适用于任意前端框架/库的前端编码、审查与测试；框架专属条款见各框架指南（如 [Next.js 条款](nextjs-guide.md)）。项目已正式采纳的规范优先于本文；本文不定义视觉风格，不决定构建与交付流程。

## 目录组织与命名

- 目录按职责分层：路由/页面、`components`（可复用 UI）、`hooks`（可复用状态逻辑）、`services`/`lib`（API 封装与工具）、`types`（共享类型）、`i18n`/文案资源；具体命名以项目既有结构为准，新文件归入既有分层，不为单个功能另起平行结构。
- 组件 PascalCase，hooks 以 `use` 开头，工具与实例 camelCase；测试文件与被测文件同目录或项目约定位置，命名可对应（`order-list.test.tsx` ↔ `order-list.tsx`）。
- 一个文件一个组件；跨页面复用的组件进 `components`，仅单页使用的留在页面就近位置，升级为共享组件时同步迁移。

## TypeScript 类型契约

- 项目启用 `strict`；新增代码不再放宽既有严格度，不随手续用 `any` 与双重断言。
- API 响应类型与后端契约字段一一对应，集中定义（`types/api` 等），不散落重复声明；后端字段变更同步类型与映射层，不让类型与实际响应漂移。
- 组件 props 显式类型（`type`/`interface` 按项目约定一种）；导出的工具函数带参数与返回类型；派生数据用类型推导，不重复手写可推导类型。

## 数据获取与服务层

- 请求统一经服务层封装：统一 base URL、错误包络解析、超时与取消；组件不直接散落 `fetch`/`axios` 调用与硬编码地址。
- 后端响应先经映射层转前端模型再进组件；接口失败按后端错误码走统一处理，不在各组件各自解释同一错误码。
- 异步三态（加载/错误/空）显式建模；列表请求处理竞态（仅采纳最后一次结果）；可取消的操作（输入联想、切换页签）实现取消，不依赖时序幸运。
- 分页、筛选、排序参数由服务层函数签名承载，不在组件拼查询串。

## 状态管理

- 区分服务端数据（请求缓存）与客户端 UI 状态（表单、开关、选中项）；服务端数据优先由请求层管理，不复制进全局 store。
- 状态提升到必要的最小公共父级即可；URL 可表达的状态（页码、筛选、选中行）放 URL，刷新与分享不丢。
- 引入全局状态库须有明确理由（跨页面共享的复杂状态），一处创建、明确作用域，不为小型页面引入。

## 错误处理与文案国际化

- 用户可见文案一律走文案资源（i18n），不在组件硬编码中文或英文句子；带参数的文案用占位符插值，不拼接句子。
- 后端错误码的展示文案与后端错误码/i18n 体系对齐：前端只负责按码取文案与兜底文案，不另造一套错误语义；未收录的错误码走统一兜底并记录原始码。
- 表单校验文案同走文案资源；错误边界（Error Boundary）兜底渲染异常，保证局部失败不白屏、不静默吞错，兜底时如实展示可操作的恢复路径。

## 构建与环境变量

- 区分编译期固化与运行时注入：带前端前缀的环境变量（如 `NEXT_PUBLIC_*`、`VITE_*`）会被打进产物——只放无环境差异的公开常量；分环境 API 地址、开关与一切敏感值走运行时注入或相对路径。
- 构建产物不做环境假设：同一产物应可部署到 dev 与 prod（与交付侧「构建期固化」约束同源）；确需编译期差异时在交付说明中显式声明并说明理由。
- 不在提交中携带本地环境文件；`.env*` 保持未跟踪（交付侧预检会拦截被跟踪的 env）。

## 安全基线

- 不将未消毒内容写入 HTML 注入通道（`dangerouslySetInnerHTML` 及框架等价物）；富文本经项目约定的消毒器处理。
- 密钥、内网地址、调试开关、未发布功能开关不进前端包与提交；前端包内容视为完全公开。
- 跳转与嵌 入外部地址用白名单或协议校验，防 `javascript:` 注入；文件下载与预览校验来源。
- 新依赖引入先过 mv-plan-tech-stack-baseline 的依赖引入评估；锁定文件随变更提交，不手动改锁文件。

## 性能基线

- 列表渲染用稳定 key（业务 ID），不用数组下标；大列表按项目约定的虚拟化/分页方案处理，不默认全量渲染。
- 静态资源按框架惯用机制引用（构建管线处理压缩与哈希），不手拼缓存破坏参数；图片按框架提供的组件/指令走懒加载与尺寸约束。
- 依赖以按需引入为默认；引入整包只为一两个工具函数前先核对替代成本。

## 测试基线

- 业务逻辑（映射、校验、状态流转）与行为改动必须有对应单测；纯展示组件按项目约定决定是否渲染测试。
- 使用项目现有测试框架与脚本；测试断言行为结果而非实现细节（不锁内部函数调用次数一类）。
- 修复缺陷时先补一条能复现该缺陷的测试再修复；测试随产品代码同一变更提交。
- 测试分层策略与覆盖率口径按项目既有约定；没有约定时如实说明口径未定义，不虚构覆盖率达标。

本文只覆盖前端编码与审查的通用工程条款；技术栈选型、本机调试、构建交付与文档产出分别归对应 skill，视觉风格以项目设计系统为准。
