# 配色推导

本文定义 mv-ui-style 家族建档时从家族参数到全套颜色 tokens 的推导步骤与对比度校验；建档一次性执行，日常新应用接入直接取 master，不重复推导。tokens 落盘形态见 [design-tokens.md](design-tokens.md)，原创性判定见 [originality-rules.md](originality-rules.md)；与 SKILL.md 冲突时以 SKILL.md 为准。

全部推导基于 OKLCH（`oklch(L C H)`：L 亮度 0–1、C 彩度、H 色相角度）。用 OKLCH 的原因：L 值与视觉亮度单调对应，对比度可以按 L 预判，推导过程可追溯。

## 推导步骤

1. **定主色 hue**：家族主色已定档蓝域 hue=264（2026-10-24 复刻修订定档：复刻用户原工具 OmniShell v0.1.0 主色 #2F6BFF；初版 2026-10-23 定 hue=250），建档时直接取用，不逐应用重选；主 hue 全文记为 `<hue>`。修订主色属家族级决策，须用户重新定档并全家族同步。
2. **推导强调色阶**（同一 `<hue>`）：
   - `accent`（主档）：亮色定档 L 0.58、C 0.2294（2026-10-24 accent 复刻修订）。依据：复刻用户原工具蓝 OmniShell v0.1.0 `--accent: #2F6BFF`（git 4863325），原值反推 oklch(0.5806 0.2289 263.9)，参数取整 L 0.58/C 0.2294/hue 264 后正推逐位还原 #2F6BFF；与苹果 systemBlue #007AFF（实测 oklch(0.603 0.218 257.4)）hue 差 6.6°、彩度偏移，并排展示普通用户仍不可指认为苹果色，过原创性红线。用于按钮底、选中态、焦点环。on-accent 校验目标 3.0（部件级门槛，2026-10-24 随修订放宽——WCAG 1.4.11 部件与大文本 AA；正文小字与链接文字不得用 accent，一律 accent-strong 过 4.5），不过 3.0 时才按 L −0.04 加深回炉；hue264 实测 0.58/0.2294 对白字 4.51 过线（兼过 4.5），无需回炉。
   - `accent-strong`（深档）：L 定档 0.44、C 定档 0.12（字面值，2026-10-24 随复刻修订复核，hue264 色域内）；用于彩底上的强调文字、链接文字，对底 4.5（hue264 实测 7.58）。过不了对比度校验时按 L −0.04 逐档加深至通过。
   - `accent-soft`（浅底）：亮色 L 0.95、C 定档 0.024（字面值；2026-10-24 修正原 C 0.03 静默出域，hue264 L0.95 色域内）；用于选中行底、徽标底。
   - `on-accent`（accent 底上的文字色）：先取白，门槛 3.0（见 accent 条）；不过 3.0 时 accent 底按 L −0.04 逐档加深直至白字通过；暗色模式反向（底色提亮、文字取深档，深字对 accent 底仍须 4.5——hue264 实测 8.81）。
   - 全谱色阶（同一 `<hue>` 的 10 档——换主题色＝整套重推，不是只换一个值）：50=0.96/0.025、100=0.92/0.05、200=0.87/0.07、300=0.80/0.09、400=0.72/0.115、500=0.65/0.13、600=0.58/0.13、700=0.50/0.125、800=0.44/0.12、900=0.36/0.10（记法 L/C）。彩度中段最高、两端收敛，高段防灰、低段防闷；hue264 实测亮端三档（50–200）仍在 sRGB 色域上限（上限=当前值），因此 accent 提彩度不牵动色阶，accent 彩度独立成参（--ui-accent-c）。组件日常只取上面的角色 token；色阶是推导骨架与扩展储备（图表分级、hover 梯度，600 档作 hover/按下加深基准），不整体暴露为组件 token。
   - 种子档位（家族参数，与主色 hue 一并定档，三选一）：标准档＝色阶骨架 C 0.13＋accent 主档 L 0.58/C 0.2294（2026-10-24 accent 复刻修订定档）；灰调档＝accent 主档 C 0.07–0.10（L 同标准带，骨架与强调 C 等比缩放）——低饱和克制配色是行业成熟做法，中文设计圈称莫兰迪色系、英文设计圈称 muted palette，讲法一致（中性近零彩度、饱和度只留给强调色），本家族「中性阶压彩度＋强调色独占彩度」与之同构；深调档＝accent 主档 L 0.42–0.50、C 0.08–0.12，白字对主档天然过 3.0（且实测过 4.5）无需回炉，strong 取 L−0.12、暗色 accent 提到 L 0.80——深色主档（藏青、祖母绿、勃艮第一类深宝石色）是奢侈品牌与金融品牌的常规锚色做法（稳重、内容优先）。通用规则：灰调/深调下全谱色阶与强调角色的 C 按主档等比缩放（k = accent 主档 C ÷ 0.2294）；语义色 C 不缩、hue 带宽不受档位影响。
   - 角色与档位的近似对应：accent-soft≈50、accent 定档 L0.58 与 600 档同 L（C 高于色阶带，复刻值特性；600 档仍作 hover/按下加深基准，深调档≈700–800）、accent-strong≈800、暗色 accent≈300；对不上时以角色值与对比度校验为准。
3. **推导中性阶**：保留主 hue 但压低彩度（C ≤ 0.02），不取纯灰——微弱色偏让界面与主色同温，这是家族观感的主要来源，取值可追溯本条。亮色角色表：bg L 0.985、surface L 1.0、border L 0.90、text L 0.25、text-muted L 0.42。暗色角色表：bg L 0.17、surface L 0.22、border L 0.32、text L 0.93、text-muted L 0.72。
4. **推导语义色**：hue 区间固定——success 145±10、warning 85±10、danger 27±8、info 250±15；C 比照 accent 主档。主 hue 落入某语义区间 ±15 内时，该语义色向区间中心收 hue 并与 accent 并排核对可辨（判定标准：并排展示，普通用户可分辨两者不同），仍不可辨时改用 C 差区分。2026-10-24 定档补充：info C 定 0.11（弱于 accent 主档，图标/边框用途，正文文字不走 info）；主 hue（264）落入 info 区间（250±15）时 info 直接取主 hue（`var(--ui-hue)`，家族唯一蓝相），不收中心。
5. **暗色映射**：与亮色同一 `<hue>`；accent 提到 L 0.76、C 定档 0.125（字面值，受 L0.76 色域上限 0.128 约束；2026-10-24 复刻修订后主档 C 0.2294 的 0.78 倍已出域，dark accent C 为独立定档不按倍率推）；accent-soft 换 L 0.28、C 0.06（上限 0.080 内）；语义色按暗色角色表提 L。不引入亮色没有的新颜色角色。
6. **对比度校验**：亮暗两套各跑一遍必查对清单，全部通过后收口。

## 对比度校验

```bash
SKILL_ROOT="/实际绝对路径/mv-ui-style"
python3 "${SKILL_ROOT}/scripts/check_contrast.py" --min 4.5 \
  <text> <bg> <text> <surface> <text-muted> <bg> \
  <accent-strong> <bg>
python3 "${SKILL_ROOT}/scripts/check_contrast.py" --min 3 \
  <on-accent> <accent> <accent> <bg>
```

必查对清单（亮暗两套各自执行）：正文与辅助文字对底 4.5；accent-strong 做文字用时对底 4.5；on-accent 对 accent 底 3.0——部件级门槛，2026-10-24 随 accent 苹果向修订放宽（苹果 systemBlue 白字 4.02 同标；WCAG 1.4.11 部件与大文本 AA），正文小字按钮与链接文字仍须 accent-strong 过 4.5；暗色按钮深字对 accent 底 4.5（hue264 实测 8.81）；焦点环对底 3（UI 部件）。border 不设 3:1 门槛——WCAG 1.4.11 只约束辨识部件与状态所必需的视觉信息，分隔线属装饰；border 作为输入框等部件的唯一辨识边界使用时局部加深（L 0.64 对 bg 实测 3.22:1 过线，两语义域已验）。校验不过按上文对应步骤的回改规则改值重跑，不降阈值、不删检查项迁就；脚本支持 hex 与 `oklch(L C H)` 两种格式，sRGB 色域外的推导值由脚本截断并在输出标注，出现截断标注时优先收 C 重推。

边界：对比度公式取 WCAG 2.1 相对亮度定义；本参考不管品牌 logo 设计与插画配色，两者按各资产的独立规范处理。
