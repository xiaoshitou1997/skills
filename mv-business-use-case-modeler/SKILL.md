# 业务用例建模

从用户描述、既有文档或代码仓库出发识别端到端业务流程，建模业务用例并落盘结构化文档，为需求细化、架构设计、任务拆解与 E2E 测试提供业务依据。本 skill 只做业务发现、用例建模与覆盖检查：不做架构决策，不写正式 PRD/HLD，不做接口文档，不实现测试代码。

`业务发现 → 用例建模 → 流程补全 → 覆盖检查`

- 画像产出为目标项目内文档 `docs/business-use-cases/`；确认后的正式 PRD/HLD 写作见 `mv-engineering-doc-writer`。
- 非功能性需求（规模、容量、网络、部署约束）采集归 `mv-nfr-intake`，本 skill 只管功能性业务流程与验证。

## 硬性规范（无例外）

- **端到端为单位**：以完整业务流程为建模单位，不按接口、方法、页面或单一功能切分用例；接口清单与功能模块清单不构成业务用例。
- **全生命周期**：每个核心业务逐项检查开始、执行、完成之后的变更、取消、退款、恢复等逆向与延续流程；查不到证据的记入覆盖缺口，不默认不存在。
- **外部参与显式建模**：跨外部系统的步骤显式写出请求内容、正常返回、失败与超时分支；不假设外部系统总是成功、即时返回或幂等。
- **不编造业务**：材料答不上的流程、规则与取值写 `Assumption` 或 `Open Question` 并注明证据缺口，不编造；矛盾无法依据材料裁断时两侧都保留并标记 `Open Question`。
- **文档是唯一事实源**：已落盘的业务用例文档以 `docs/business-use-cases/` 为准，不靠会话记忆；条件变化改文档并记变更，会话口径与文档冲突时以文档为准。
- **结论范围对齐**：覆盖结论只对实际核验过的用例与场景下结论；「已覆盖」必须有对应 E2E 场景条目，「复核完成」的声明范围必须与实际检查范围一致。
- **术语一致**：业务术语、参与者名与用例名全文一致、一词一义；同一业务动作在目录、用例与场景中不换称谓。

## 输入与证据

按优先级收集证据，结论保留出处（文件路径或用户原话）：

- 用户对产品或业务的描述：明确为决策的按 `Decision` 处理，其余按待确认处理。
- 项目既有需求文档、设计文档、README 等材料：按 `Fact` 引用，保留既有术语与标识符。
- 代码仓库已实现的业务逻辑：以实际实现为准；实现缺失不等于业务不需要，二者不一致时记 `Open Question`。

语句分类沿用 `mv-engineering-doc-writer` 的口径：`Fact`、`Requirement`、`Decision`、`Assumption`、`Open Question`。

## 工作流

1. **业务发现**：判定输入形态（纯描述／有文档／有代码），收集证据；识别业务领域、参与者（用户角色与外部系统）与业务能力，回答「业务是什么」——列出系统要支持的业务及每项业务的目标；产出一版用例目录草稿。
2. **用例建模**：对目录中每个核心用例展开完整端到端用例——前置条件、参与者、主流程（逐步骤区分本系统动作与外部系统交互）、替代流程、异常流程、业务规则、验收条件与业务对象状态变化，回答「业务如何完成」；落盘见「产物与落盘」。
3. **流程补全**：按 [references/completion-checklist.md](references/completion-checklist.md) 逐用例核对生命周期逆向与延续链路（变更、取消、退款、恢复、超时、补偿）与异常来源（输入错误、外部失败、并发冲突、业务拒绝、权限不足），补齐缺失分支；外部系统失败分支逐步骤落位。
4. **覆盖检查**：为每个用例生成 E2E 业务测试场景（正常／替代／异常／恢复），回答「业务如何验证」；建覆盖矩阵（用例 × 场景 × 状态），汇总假设、待确认问题与覆盖缺口，落盘并在会话结束时报告。

建模中途发现新业务或用例遗漏时，先补目录再展开，保持目录与用例文件一致。

## 产物与落盘

产出落盘目标项目 `docs/business-use-cases/`（文档缺失时新建并纳入版本管理）：

- `overview.md`：业务领域与能力概览、参与者清单、用例目录（编号、名称、参与者、目标、生命周期阶段、覆盖状态）、生命周期与 E2E 覆盖矩阵、假设与开放问题、变更记录。按 [references/overview-template.md](references/overview-template.md) 落盘。
- `use-cases/<编号>-<英文短名>.md`：每个端到端用例一文件，含完整流程、业务规则、异常处理、验收条件与 E2E 测试场景。按 [references/use-case-template.md](references/use-case-template.md) 落盘。

用例编号自 `BUC-001` 顺延，废弃用例在目录中标记废弃并保留编号，编号永不复用。增量建模时只改涉及的用例文件，并同步 overview 的目录、矩阵与变更记录。

## 输出

产出与更新 `docs/business-use-cases/`（overview 与各用例文件，含生命周期与异常处理、E2E 场景、覆盖矩阵、假设与开放问题、变更记录）；收尾一次说清：用例总数、覆盖状态分布、假设与待确认问题数、覆盖缺口清单。

## 边界

正式 PRD／HLD／LLD／RFC 写作与 API 文档归 mv-engineering-doc-writer，本 skill 产出的业务用例文档是其上游业务依据，不是其中任何一种；非功能性需求采集归 mv-nfr-intake；业务流程图绘制归 mv-diagram-drafter，图插入文档归 mv-doc-figure-placement，本 skill 默认产文字文档不出图；E2E 自动化测试代码实现见 mv-java-backend-standards。
