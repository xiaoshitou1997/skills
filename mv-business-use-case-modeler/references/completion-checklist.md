# 流程补全与覆盖检查清单

适用于 mv-business-use-case-modeler 工作流第 3 步（流程补全）与第 4 步（覆盖检查）：逐用例核对，结果落 overview 的生命周期与 E2E 覆盖矩阵；清单项查不到证据的记覆盖缺口并登记编号，不默认不存在。

## 生命周期补全

每个核心用例逐项回答「有没有这条链路、走查过没有」：

- [ ] 正常完成后的延续动作（查询、下载、开票、评价等，按业务实际）
- [ ] 变更：改参数、升级／降级、换绑等
- [ ] 取消：未完成时撤销；已完成时撤回及其限定条件
- [ ] 逆向：退款、退货、注销、销户等，金额与资源如何回退
- [ ] 恢复：中断后续办、失败后重试入口、挂起与恢复
- [ ] 超时与补偿：外部无响应时的等待、重试、补偿、人工介入
- [ ] 终态：哪些状态不可再变，关联数据的保留与清理

## 异常来源核对

逐步骤检查五类异常来源，每个异常分支必须有明确处理与业务结果（提示、回滚、补偿、转人工），不允许「无处理」：

- [ ] 用户输入错误
- [ ] 外部系统失败、超时、部分成功
- [ ] 并发冲突：重复提交、库存与名额竞态
- [ ] 业务规则拒绝：余额、限额、资格、时效
- [ ] 权限不足

## 外部系统核对

- [ ] 每个外部步骤写明请求内容、正常返回、失败返回、超时行为
- [ ] 部分成功（本系统已提交、外部未确认）的处理：对账、补偿、状态机
- [ ] 返回不匹配（格式错误、未知业务码）的处理

## 覆盖检查

- [ ] 每个用例至少 1 条正常场景，外部失败与业务拒绝至少其一有异常场景
- [ ] 每条 E2E 场景追溯到用例流程步骤编号或异常编号
- [ ] 覆盖状态口径与 overview 一致；「已覆盖」必须有场景条目支撑
- [ ] 全部假设与开放问题登记 overview，标注影响用例
- [ ] 覆盖结论只声明实际核验过的范围，不把未查项说成已查

边界：本清单是建模完备性工具，不判定代码实现正确性；E2E 自动化测试代码实现见 mv-java-backend-standards。
