# Docker 交付安全模型（部署侧）

脚本使用调用者或 agent 的权限运行。Skills 提供操作指导与工具，不承担沙箱、授权网关或云端密钥存储的职责。

**当前 dev/prod 部署、回滚、状态查询和目标 plan 均关闭；脚本不访问远端、不写目标文件、不生成收据，也不执行自动恢复。** 以下交付控制是恢复入口前的要求。

## 控制措施

1. **用户授权**：生产部署/回滚、强制 Git 操作、数据库变更和远端写入需要明确的用户意图。生产入口目前无条件拒绝；恢复后 `--approve-prod` 也不能证明用户已经授权。
2. **平台控制**：本仓库分发不自动安装命令 Hook。团队控制由 agent 权限、项目 Hook、仓库分支保护和 CI 落实，skill 指令本身不是强制执行机制。
3. **秘密信息**：项目 `.env.dev`、`.env.prod` 和私钥不得进入 Git 或命令日志。用户负责权限与密钥存储。恢复交付前须解决配置传输与权限保护；当前入口不传输 `.env` 与 Compose 文件。
4. **生产验证**：恢复生产交付前须设计并验证镜像 Image ID、同一 Image ID 的 dev 验证证据及真实 readiness 探活门禁。当前脚本不执行这些检查，也不生成收据。收据只记录本工作机执行的验证，不是签名证明。
5. **失败恢复**：恢复部署前须设计并验证失败恢复，包含配置及完整历史记录；当前脚本不执行恢复。数据/数据库迁移、新环境配置和外部副作用不会自动撤销；回滚后检查服务实际状态。
6. **可选扫描策略**：镜像构建期扫描（Trivy/Gitleaks）见 [构建安全模型](build-security-model.md)；CI 应落实严格策略，不能将跳过扫描解释为通过。

## 部署前提

dev 与 prod 使用不同的 SSH 目标和隔离的应用目录。主机密钥按 SSH 的 `known_hosts` 机制验证，不禁用该检查。限制 Docker daemon 的访问权限，查看 `docker compose config` 时避免输出秘密信息；不将不可信的镜像名或环境值传入部署命令。跨栈安全政策、数据分级与漏洞响应归 `mv-security-standards`，本文件只保留 Docker 交付与部署侧控制。
