# Spring Boot Standards

## 作用与优先级

这是**规范型 Skill**，在 Agent 编码、审查、测试期间引用；不负责编排 Spec/Plan/Tasks，不直接启动、Commit 或部署。适用于 Spring Boot / MyBatis-Plus；其他 Java 框架借鉴通用条款，不强加不兼容的框架约束。

优先级：用户明确需求和项目已正式采纳的规范 / ADR → 本规范 → 框架默认约定。现有代码结构优先保持一致，若规范与现有项目矛盾，应展示差异并提出迁移计划，不直接全仓重构。

开始前确认本次业务范围、需求来源、版本及优先级，不默认原型、旧文档或现有代码永远权威。代码用于说明当前实现；与已确认需求不一致时记录差距，不反向改写需求。涉及表或接口设计先核对当前 DDL、迁移与契约基线，保留必要语义增量，避免并行修改覆盖彼此决策。

## 关键规则

1. `Controller` 处理路由、校验、协议映射，不编写核心业务或直接操作 Mapper；`Service` 处理业务/事务；`Mapper` 处理数据库持久化。以项目实际边界为准，不形式化地给所有简单逻辑强加接口与实现类。
2. 命名语义明确，类与方法 camelCase/PascalCase、数据库字段 snake_case。DTO/VO/API Contract 不直接泄露持久层 Entity。
3. 按项目既有 API 响应契约返回数据，不擅自把所有接口改为新的 `ApiResponse`。使用 Bean Validation 做输入校验，保证客户端看到明确错误码和不暴露内部异常。
4. 捕获异常必须有实际处理意图；不得吞异常或使用 `printStackTrace()`。异步任务、批处理和后台作业必须正确传播或记录失败状态，不能把“请求已接受”或“没有异常抛出”当成执行成功。日志采用 SLF4J 参数化，避免重复记录相同 stacktrace、泄露 Token/密码/PII 或全量请求体。
5. 禁止无界全表列表、循环单行查询 N+1；注意索引/事务/幂等/并发安全；SQL 使用参数绑定，查字段按需，不在生产代码里使用 `SELECT *` 作为默认查询模式。
6. 事务置于真实业务边界；理解 Spring 代理与自调用问题，避免网络 IO/长时间等待占用 DB 事务。`rollbackFor = Exception.class` 在业务需要时指定，不假设每个事务都必须模板式声明。
7. 配置与 Secret 分离，敏感信息经运行时环境变量或 Secret Store 注入；不硬编码密钥，不把 `.env.prod` 提交到 Git。支持按 profile 环境差异化。
8. 对高风险逻辑补齐单测和必要的集成测试：正常路径、边界条件、异常和并发/事务场景。使用项目现有 JUnit/Mockito/Testcontainers 等工具，不为规范而更换框架。
9. 改动现有系统时保持最小必要变更，优先遵从项目已有模块、依赖版本与兼容性约束。涉及契约、数据库、升级或不兼容 API 要更新对应文档和迁移建议。
10. 集成组件封装鉴权、协议包络、超时等技术机制，业务侧保留业务接口与决策；优先使用现有客户端的声明能力，不为复用另造通用路径调用门面或代理栈。只实现组件的任务，不自动扩展成服务接线与业务编排。

## 详细参考

代码结构、命名、API、接口文档、日志、数据访问和单测的建议见 [references/java-guide.md](references/java-guide.md)；编写或审查设计、接口文档时读取其中的文档条款。文件仅为工程规则，不是独立 Reviewer/Quality Gate Skill。规范中的举例不应覆盖项目实际库版本或性能特征。

## 输出

在交付说明中列出关键规范决策、针对本次变更的遵循/偏离原因、执行的验证结果；不要泛泛输出整本 Java 规范。

## 自动验证与边界

本规范是项目规范的补充，供支持 Agent Skills 的编码助手编码、自检与审查时引用。优先运行项目已有检查；可选择执行本 skill 的 `scripts/quality-check.sh`（参数为 `quick` 或 `full`）。从加载的 SKILL.md 定位脚本绝对路径，保持用户项目为工作目录。静态规范和自动检查不能互相替代。
