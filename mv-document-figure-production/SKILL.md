# 文档配图制作

负责图的来源、渲染和在目标文档中的放置与验证。Word、PPT 编写过程中新增图和修改已有图均适用；文档正文、结构和事实核验仍由文档的编写流程负责。

## 脚本位置

`SKILL_ROOT` 必须显式设为本次加载的 skill 目录，不能假设环境已提供；脚本路径恒加引号。从用户文档所在项目目录执行命令，不在 skill 目录内产生运行时文件。

```bash
SKILL_ROOT="/实际绝对路径/mv-document-figure-production"
python3 "$SKILL_ROOT/scripts/office_figures.py" --help
```

## 工作流程

1. 确定文档格式、图的目的与插入位置，核对图中信息的来源和正文术语。已有文件先查看目标页、段落或形状，明确图尺寸；图标编号与图注由文档编写流程维护。
2. 按图形选文本图源：时序、状态、ER 等结构图优先 Mermaid；需要精确视觉布局的架构、拓扑、流程、页面示意图用 HTML/内联 SVG；已有真实页面优先在有权访问的本地环境截图。按需读取 [渲染指南](references/rendering.md)。
3. 在目标文档项目存放 `fig-src/<图名>.mmd` 或 `.html` 等可编辑图源，在 `fig-out/<图名>.png` 存放渲染结果。截图的来源、页面状态与取图时间随文档记录；不将仅有 PNG 的图称为可编辑图源。先核对图的文字、裁切、分辨率和来源事实。
4. Markdown 在目标阅读器支持时可直接嵌入 Mermaid 源码，否则引用已渲染的本地图片。Word/PPT 使用已渲染的 PNG，在**写作文档的同一任务中**插入成品，不把制图完成误作交付完成。
5. 对新建的 Word/PPT，先用该格式的文档制作能力生成正文或幻灯片，再在确定的位置插图；对已有文件先列举目标图或设置唯一锚点，再插入或替换。按需读取 [Office 配图指南](references/office-figures.md)。本 skill 的脚本编辑图形，不生成任意正文或整套幻灯片。
6. 写出新的文档文件后，复查图文一致、图注、比例、位置、裁切、与页面背景的对比和文件可打开性。能使用目标应用时逐页查看；只运行了 ZIP/XML 检查时如实记录尚未进行视觉检查。

## 不可违反的原则

- 修改图先修改保留的图源，再渲染；真实页面截图保持来源与时间可追溯。不为了图的美观补造未确认的组件、流程或指标。
- 本地渲染敏感文档的图；不要将含敏感信息的图源上传到在线渲染服务。依赖缺失时报告缺失，不默默调用会联网安装依赖的 `npx`。
- 保持目标格式可用。Office 文件只能向**不同的输出路径**写入；先预览定位候选项，目标不唯一时停止，绝不以“图注前最近一张图”自动修改。
- Word/PPT 替换只改变被选中的一张图；即便几处共用同一媒体文件，也不能覆写原媒体使其他位置一起变化。
- 不把 Markdown 的 Mermaid 块直接当作 Word/PPT 图片交付；图源、图片、目标文档三者均应存在且对应。
- 冲突时按用户明确需求 → 本规范 → 工具默认行为处理；用户指定的制图格式、布局和现有项目约定优先。

## 交付与边界

说明图源与图片位置、插入/替换的目标文档、目标图的定位依据和实际验证结果。工程文档的内容编写与评审见 mv-engineering-doc-writer；Word/PPT 正文与版式由对应的文档制作能力负责。仅单独要求绘制图或调整文档里的图时，可独立使用本 skill。
