# 测试规范

面向 mv 团队全部项目的测试资产：定「哪层测什么、测到什么程度」，并给出各端测试代码写法。产品代码规范与测试的构建期执行通道不归本 skill。

## 作用与优先级

这是**规范型 Skill**，在编写、审查、补齐测试时引用；不负责搭建 CI 流水线，不直接启动应用，不写部署验证。优先级：用户明确需求和项目已采纳的规范 / ADR → 本规范 → 框架默认约定。项目已有覆盖口径与本规范冲突时项目优先，偏离记录进交付说明。

## 开始前确认

开始前确认变更范围与类型（新增功能、修缺陷、重构）、项目已有测试资产与既有覆盖口径、涉及端（后端、admin、user、H5/小程序）。修缺陷场景先确认可复现路径。

## 关键规则

1. 分层默认口径：**单测覆盖纯逻辑（工具、计算、状态转换、边界条件），集成测试覆盖持久化与事务（真实数据库，经 Testcontainers），E2E 只覆盖核心用户路径冒烟**；不用全量 E2E 追求覆盖率。
2. 后端每个新增或修改的 Service 公有方法至少有一条失败路径用例；Controller 层不重复测 Service 已覆盖逻辑，经 Web 层切片测试只测参数校验、错误码映射与鉴权。
3. 前端组件测试断言行为不断言渲染快照：加载、错误、空三态、表单校验分支、权限分支有交互断言；纯展示组件不强制建测试文件。
4. E2E 冒烟固定清单：登录、核心列表页加载、一条核心写操作、登出；随发布执行，不随每次提交执行。
5. 覆盖率基线：后端核心包行覆盖 ≥70%、分支 ≥50%（项目可上调，下调须项目 ADR 记录）；统计范围排除生成代码与纯 DTO/VO。项目未配置覆盖率门槛时不擅自引入，先与团队确立。
6. 外部依赖替身：数据库用真实实例（Testcontainers），不 mock 数据访问层；HTTP 外部依赖用 WireMock 一类桩；时间用注入时钟，不在测试内 sleep 等待。
7. 测试数据：集成测试经版本化迁移脚本建 schema，用例内自建自清数据，用例间不依赖执行顺序。
8. 缺陷修复先补一条复现该缺陷的失败用例再修复，修复后该用例转绿；不补用例的修复在交付说明说明原因。
9. 测试代码与产品代码同一分层纪律：一个测试类/文件对应一个被测单元，命名 `<被测单元>Test`（Java）或 `<被测单元>.test.tsx`（前端），不建跨单元共享的巨型测试类。
10. 涉及认证上下文的集成测试设置真实主体对象，不用静态 mock 框架替代认证链路。

## 输出

测试证据按四档如实记录：编译、单测、集成测试、E2E 冒烟；每档写明执行命令与结果，未执行的层明确写「未执行」，不虚构通过。交付说明列出新增用例清单、覆盖率数字（配置了门槛时）与豁免偏离项。

## 边界

产品代码分层、DTO、事务写法见 mv-backend-standards；组件与服务层写法见 mv-frontend-standards。本机把应用跑起来人工调测（含联调请求构造）归 mv-local-debug。测试的构建期执行通道（CI 步骤、流水线）由项目承担，本 skill 只定测试内容与底线。
