# 集成与失败处理模式

配合 mv-architecture-standards 使用；适用于跨服务、第三方系统、消息与长流程。模式是默认建议，项目已有成熟方案且能说明取舍时以项目为准。

## 防腐层

- 第三方 SDK、协议与数据模型在边界处转换成本方领域模型，不让外部类型渗透到 Service 与领域层。
- 防腐层负责：鉴权签名、协议包络、超时、重试、错误码映射、字段校验与脱敏；业务层只依赖本方接口。
- 换供应商时只改防腐层；防腐层必须有契约测试或真实环境联调证据。

## Outbox

适用：本地事务成功后必须可靠投递事件，且不能接受双写丢失。

1. 业务表与 outbox 表在同一本地事务写入。
2. 独立投递器按主键游标读取未投递记录，发送后标记；失败重试有上限并进入死信/告警。
3. 消费端按事件 ID 幂等；重复投递不产生重复副作用。
4. outbox 表定期清理，保留期覆盖排障与对账窗口。

## Saga

适用：跨服务长流程，无法用单事务完成，且需要明确补偿。

- 编排式（一个协调者驱动）优先，流程与补偿逻辑集中可见；参与者只提供幂等命令与补偿接口。
- 每一步写明：成功动作、失败动作、补偿动作、超时、重试上限、人工介入条件。
- 外部副作用（发消息、扣款、发货）不可自动补偿的，先做状态预留或对账，不假设能回滚。

## 幂等

- 写接口按业务唯一键或客户端请求 ID 去重；数据库唯一约束是最后防线。
- 消费端以事件 ID/消息 ID 去重；处理结果落库后再确认消息。
- 重试不改变业务语义；非幂等操作不自动重试。

## 超时、重试、熔断与限流

- 所有外部调用显式设置连接与读取超时；超时值小于上游请求预算。
- 重试只用于瞬时故障，指数退避 + 抖动 + 次数上限；非幂等、参数错误、鉴权失败不重试。
- 熔断按失败率与慢调用比例触发，半开探测恢复；降级返回明确业务语义，不静默吞错。
- 入口与关键下游设置限流；限流阈值来自容量评估，不拍脑袋；被限流返回约定错误码并记录。

## 契约与版本

- 接口契约以 OpenAPI/IDL/消息 schema 为准，代码与契约同源；契约变更按兼容性分级。
- 新增字段向后兼容；删除/改语义走新版本或 expand–contract；消费端容忍未知字段。
- 消息 schema 带版本；消费者按版本兼容窗口升级，不假设所有消费者同时更新。

## 观测

- 每个集成点记录：调用方、被调方、耗时、结果、重试次数、错误码；链路追踪透传请求 ID。
- 异步链路记录生产、投递、消费、失败与死信；积压与消费延迟有告警。
- 失败日志含定位所需上下文，不含秘密与全量敏感报文。

具体实现按项目技术栈；认证与权限实现归 mv-backend-standards，安全控制归 mv-security-standards。
