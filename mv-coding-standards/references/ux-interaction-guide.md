# 交互与体验规范（框架中立）

适用于管理端与用户端网页的界面布局、交互设计与异常态处理；编写、修改与评审页面时并入检查，列表批量处理等能力按业务需要采用。与编码条款同源的原则不重复展开（组件分层、类型契约、服务层三态见 [frontend-guide.md](frontend-guide.md)），本文只管「页面做出来是否可用、一致、容错」。项目已正式采纳的设计系统与交互规范优先于本文；视觉风格本身（配色、字体、品牌感）仍以设计稿为准，本文不定义；品牌触点接线（图标、分享卡、系统页与小程序配置）见 [frontend-guide.md](frontend-guide.md)「品牌触点接线」。

## 布局与信息层级

- 布局范式稳定：列表页、表单页、详情页各自维持同一骨架（筛选区、工具栏、表格、分页的相对位置固定），同类页面不各摆各的；新页面套用项目既有页面模板，不另起炉灶。
- 信息层级靠排版表达：页面标题 → 区块标题 → 字段标签层级清晰，重要操作与次要操作用主/次按钮区分（一个区块至多一个主按钮），不靠加粗与颜色堆叠强调。
- 表单按业务分组排版，相关字段相邻；长表单分步或分区，避免单屏无结构堆叠；标签位置在同一表单内统一（不一半左置一半上置）。
- 对齐与间距走项目设计令牌（与 frontend-guide 样式条款同源），不散落魔法数值；同类信息同列对齐（金额右对齐、状态列居中等按项目既有约定）。

## 状态与即时反馈

- 每个交互元素具备完整状态：默认、悬停、聚焦、禁用、加载中；按钮点击后有可感知反馈（loading 态或结果提示），不出现「点了没反应」的等待。
- 操作结果即时反馈：成功轻提示、失败明确报错，破坏性结果用确认对话；连续操作（批量删除、导入）有进度指示与结束汇总。
- 反馈就地呈现优先于全局弹窗：表单校验错误标在字段旁，列表操作结果提示在列表区；弹窗只用于必须打断的场景。
- 页面级异步数据维持三态页面：加载骨架屏或指示器、错误态带重试入口、空态带引导动作；三态不全的页面按缺陷处理（与 frontend-guide 服务层三态条款同源）。

## 操作流程与效率

- 流程贴合业务顺序：录入页字段顺序、向导步骤与线下业务单据/审批流一致，不按技术表结构排序；常用路径步骤数最少，低频高级选项收进折叠或次级入口。
- 按任务决定列表能力：数据量大或条件检索频繁时提供筛选、排序与服务端分页；大量重复操作且业务允许时提供批量操作；有数据交换需求且获授权时提供导入导出。无需求或缺少后端能力时不伪造入口；相同业务场景保持一致，并记录未提供能力对效率的影响。筛选变化时重置页码，区分无数据与筛选无结果；需要恢复条件时持久化非敏感筛选状态，避免把敏感条件写入 URL。
- 批量操作显示影响范围、跨页选择语义及有权限的实际对象；提交前确认高危动作，处理完成汇总成功、失败与可重试项，不把部分成功当成全部成功。导入提供模板、格式和大小限制、逐行错误及重试方式；导出明确筛选范围、数据权限及敏感字段处理，大任务显示进度与完成结果。服务端重新校验权限、数据与处理范围。
- 重复录入系统消除：能从上下文带出的字段自动带出（时间、操作人、上级单据），能选不填（下拉、选择器），记忆用户上次选择须显式声明且可改。
- 键盘可达：所有操作可用 Tab 到达、Enter 提交、Esc 关闭弹层；表格支持快捷键时在界面标注；焦点顺序与视觉顺序一致，焦点样式可见不删除。

## 表单校验与容错

- 前端在字段失焦即校验必填与格式，范围与可在客户端判断的跨字段关系在提交前统一校验；错误标在字段旁并给出修正提示，提交失败保留用户输入并将焦点导向错误摘要或首个错误字段。前端限制只改善交互，后端必须独立校验所有外部输入并授权，见本 skill spring-guide「Web 与校验」。
- 错误提示讲人话：说明哪个字段、什么错、怎么改（「开始时间不能晚于结束时间」），不输出裸错误码或堆栈给用户；同一错误在前后端文案一致。
- 删除、作废、批量变更、发布等高危操作提交前展示对象、影响范围、不可逆后果与确认动作；可恢复场景优先提供经后端实现和验证的撤销或恢复，不可恢复时明确说明并提供符合数据保护要求的操作审计。日志用于追溯，不能冒充撤销；超时结果未知时先查询操作状态，不盲目重复提交。
- 未保存离开有拦截（路由守卫提示），关键表单默认本地草稿自动暂存并在返回时提示恢复，不做静默丢弃；草稿与当前数据版本不匹配时不静默覆盖。

## 用词与可学习性

- 同一概念全站一个词：按钮「新增」就不混用「添加」「创建」，「启用/停用」不混用「开启/关闭」；术语表以项目设计系统为准，没有时新建并保持追加式维护。
- 提示文案统一语气：面向操作者的直接陈述（「已保存」「还有 2 项未填写」），不用技术口吻与客套话；数字、单位、日期格式全站一致。
- 新功能提供轻量引导（空态提示、字段旁说明、一次性浮层），引导可关闭且不重复弹出；帮助入口固定位置。
- 布局与交互范式跨页面复用：用户在 A 页学会的操作在 B 页同样成立；破坏既有范式前先论证收益，改则全站同步。

## 视觉与状态可视化

- 色彩用于区分状态与语义（成功/失败/警告/进行中），不做纯装饰；同一语义色全站同义，不一个页面绿色报错另一个页面红色成功。
- 状态必须可视化：处理中、已完成、已作废等业务状态在列表与详情有明确标识（徽标、标签），不只靠背景色区分（兼顾色弱与灰度打印场景用图标或文字并列）。
- 简约低干扰：动效克制（200ms 内的过渡），不用常驻动画与闪烁；装饰性元素不挤压信息密度；视觉还原以设计稿为准，与本文冲突时设计稿优先并记录。

## 权限视图与异常页面

- 按权限区分视图：无权限的功能入口不渲染（不向界面暴露不可用入口），页面内字段级权限（脱敏、只读）跟随项目权限模型；直接访问页面及权限失效后的 403 须有可理解的反馈。前端隐藏不构成授权，后端独立校验操作与资源范围。
- 异常页面完备且可操作：404/403/500 各有页面，给返回入口或联系渠道；读取超时提供重试，写操作结果未知时先查询状态或采用服务端幂等机制；加载失败区分「无数据」与「加载失败」，不用同一个空态糊弄。
- 会话超时引导重新登录并按安全策略保留目标页；需要保留表单时采用项目批准的草稿或临时存储机制，控制敏感数据、保存期限及共享设备风险，无法安全恢复时明确提示。

## 多分辨率适配

- 以项目声明的目标分辨率为准（管理端常见最小 1280px 宽），低分辨率不出横向滚动条或给出明确降级说明；表格列宽、弹窗尺寸设最小值并随视口伸缩。
- 移动端/平板支持按项目约定，支持时导航、表格、表单有对应降级形态；不支持时在窄视口给出明确提示，不出半坏的布局。

## 验收与输出

- 根据实际功能走查完整主流程及加载、空数据、无搜索结果、失败、超时、无权限和部分成功等适用状态；核对操作反馈、重复提交、筛选分页、批量及导入导出边界。用键盘走查焦点顺序、可见焦点和弹层关闭/焦点返回，在项目支持的视口及设备上检查内容和操作是否可达。
- 输出按实际发现记录「风险点 → 影响 → 优化方案 → 状态/验证证据」；区分已修复、待处理和未验证，不虚构页面缺陷或已完成的测试。
