# 可访问性与性能预算

配合本 skill 使用。可访问性是交付质量的一部分，性能预算是设计约束；两者都在开发与验收阶段验证，不等到上线后补。

## 可访问性基线

目标：WCAG 2.1 AA 的核心要求；项目有更高合规要求时按项目执行。

- **键盘可达**：所有交互元素可 Tab 到达、可 Enter/Space 触发、可 Esc 关闭浮层；焦点顺序与视觉顺序一致。
- **焦点可见**：不全局移除 `:focus-visible`；浮层打开后焦点进入浮层，关闭后回到触发元素。
- **语义结构**：标题层级连续；表单控件有 label；按钮与链接语义正确；图标按钮有可访问名称。
- **对比度**：正文与背景对比度 ≥ 4.5:1，大文本 ≥ 3:1；不只用颜色传达状态。
- **表单容错**：错误信息与字段关联，说明如何修正；必填与格式要求提前说明；不用占位符替代 label。
- **动态内容**：加载、错误、空态有可感知提示；异步更新用 live region 或等效机制；尊重 `prefers-reduced-motion`。
- **图片与媒体**：有意义的图片有 alt；装饰图片空 alt；视频有字幕或文字稿（按项目要求）。
- **触控目标**：移动端可点击区域足够大，间距不导致误触。

## 性能预算

按项目与端设定预算，写入项目文档并在 CI 或验收中检查：

| 指标 | 建议基线 | 说明 |
| --- | --- | --- |
| LCP | ≤ 2.5s | 首屏主内容；按实际网络与设备校准 |
| INP | ≤ 200ms | 交互响应；长任务拆分 |
| CLS | ≤ 0.1 | 图片/字体/广告位预留尺寸 |
| 首包体积 | 按项目设定上限 | 路由级代码分割；不在首包引入大依赖 |
| 图片 | 按视口与倍率生成 | 懒加载、现代格式、避免布局跳动 |
| 列表 | 分页或虚拟滚动 | 不在首屏渲染无界列表 |

预算不是装饰指标：超预算的依赖或页面需要说明理由与替代方案；不把「本地快」当用户体验结论。

## 验证

- 用浏览器 DevTools、Lighthouse 或项目既有工具跑可访问性与性能检查；记录环境、网络与设备。
- 键盘走查覆盖主流程；屏幕阅读器抽查关键页面（项目有要求时）。
- 性能数据区分开发机、预览环境与生产；未执行写「未执行」，不虚构分数。
- 组件测试覆盖加载、错误、空态、键盘操作与焦点管理的关键路径。

具体交互模式见 ux-interaction-guide；视觉还原与设计令牌见本 skill 正文，样式实现细则见 frontend-guide。
