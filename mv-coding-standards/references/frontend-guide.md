# 前端工程规范（框架中立）

适用于任意前端框架/库的前端编码、审查与测试；框架专属条款见各框架指南（如 [Next.js 条款](nextjs-guide.md)）。项目已正式采纳的规范优先于本文；本文不定义视觉风格，不决定构建与交付流程。

## 目录组织与命名

- 目录按职责分层：路由/页面、`components`（可复用 UI）、`hooks`（可复用状态逻辑）、`services`/`lib`（API 封装与工具）、`types`（共享类型）、`i18n`/文案资源；具体命名以项目既有结构为准，新文件归入既有分层，不为单个功能另起平行结构。
- 组件 PascalCase，hooks 以 `use` 开头，工具与实例 camelCase；测试文件与被测文件同目录或项目约定位置，命名可对应（`order-list.test.tsx` ↔ `order-list.tsx`）。
- 一个文件一个组件；跨页面复用的组件进 `components`，仅单页使用的留在页面就近位置，升级为共享组件时同步迁移。

## TypeScript 类型契约

- 项目启用 `strict`；新增代码不再放宽既有严格度，不随手续用 `any` 与双重断言。
- API 响应类型与后端契约字段一一对应，集中定义（`types/api` 等），不散落重复声明；后端字段变更同步类型与映射层，不让类型与实际响应漂移。
- API 类型来源二选一并全项目一致：经 OpenAPI 生成器从后端 `/v3/api-docs` 生成，或从后端契约 DTO 集中映射；来源口径与同步责任见 mv-design-standards「共享契约与类型同步」。
- 枚举型字段按消费建模：前端区分取值（按值分支、逐值样式）时定义为与后端契约一致的字面量联合类型，集中一处，逻辑分支走枚举字面量不走展示名；仅原样展示或回传筛选参数的场景用 `string`，不为无消费者的取值全集维护联合类型。
- 组件 props 显式类型：对象形状用 `interface`，需要联合、映射或条件类型等 `interface` 表达不了的形态时用 `type`；导出的工具函数带参数与返回类型；派生数据用类型推导，不重复手写可推导类型。

## 数据获取与服务层

- 请求统一经服务层封装：统一 base URL、错误包络解析、超时与取消；组件不直接散落 `fetch`/`axios` 调用与硬编码地址。
- 后端响应先经映射层转前端模型再进组件；接口失败按后端错误码走统一处理，不在各组件各自解释同一错误码。
- 枚举取值全集（筛选、下拉等场景）走后端枚举字典端点按请求 locale 取得，由服务层缓存复用；不在前端硬编码取值全集，不维护「取值 → 展示名」映射表。按取值配置的 UI 呈现（颜色、图标）收敛在映射层，未收录取值走默认样式兜底。
- 异步三态（加载/错误/空）显式建模；列表请求处理竞态（仅采纳最后一次结果）；可取消的操作（输入联想、切换页签）实现取消，不依赖时序幸运。
- 分页、筛选、排序参数由服务层函数签名承载，不在组件拼查询串。

## 前后端联调信息

- 按本次目标环境收集信息：先采用用户本次明确提供或确认的信息，再读取下述固定入口、项目正式采纳的环境/部署文档与接口契约，最后核对当前请求封装、代理和后端路由实现。记录每项来源、环境和确认状态；固定入口与实际配置或其他来源不一致时列出差异，请用户或项目责任人确认，确认前不连接或改写相关配置。已生效的项目配置与代理是实际行为的真源，固定入口仅供查找和交接，不被 Vite、Taro 或项目自动加载。
- 明确前端请求的 base URL、API 前缀、各层是否保留或改写前缀、后端实际路由及接口方法与路径；区分浏览器访问地址、开发代理目标和后端监听地址，核对拼接结果，避免前缀重复或丢失。地址按目标环境提供，不推测主机、端口或路径。
- 按接口契约确认认证方式、登录与令牌取得方式、请求头或 cookie、跨域凭据与 CSRF 要求、过期及无权限响应；测试账号和凭据通过项目认可的安全渠道取得，不写入源码、日志、前端产物或交付说明。
- 信息缺失时只向用户补问本次目标端所需的缺项，并说明已查来源；已确认的非敏感信息按下述规则写回固定入口，凭据只问获取方式或配置键，不索取凭据值。来源冲突、目标不可访问或用户未提供缺项时，记录受阻范围及待确认对象，停止依赖该信息的连接与配置；不以示例地址、mock 成功或猜测认证方式冒充联调完成。可继续不依赖这些信息的工作。
- 按项目已有启动和验证命令，在目标环境发起契约允许的只读请求，记录实际请求路径、状态码、响应包络或错误码与页面结果；涉及认证时覆盖已认证及未认证/无权限路径。记录使用的命令或操作、目标端及环境、观察结果和失败症状，隐藏凭据与敏感数据；无法执行的检查写明未执行及原因，不以构建或 mock 测试代替真实联调。

## 联调信息固定入口

- 本 skill 在宿主保存非敏感联调信息：状态根目录使用 `MV_CODING_STANDARDS_HOME` 指定的非空宿主绝对路径，未设置或为空时使用 `~/.mv/coding-standards/`；文件为其下 `integration/<项目键>.json`。项目键为项目根目录真实绝对路径的 SHA-256 小写十六进制：使用 realpath，Windows 将反斜杠转为正斜杠并将路径转为小写，再按 UTF-8 编码计算。每次先确认项目根目录并计算项目键；不同工作树的真实路径分别存储。
- 文件为 UTF-8 JSON 对象，`schemaVersion` 固定为数字 `1`，`projectRoot` 保存上述规范化路径，`entries` 为数组；每条记录以 `app`、`environment`、`platform` 三者共同唯一定位：`app` 为相对项目根目录的应用路径，单应用用 `.`；`environment` 为项目确认的环境名；`platform` 为 `web`、`h5` 或 `weapp`；不跨应用、环境或端继承地址。
- 每条记录的 `values` 对象可包含：`baseUrl`（前端请求基地址或同源相对路径）、`apiPrefix`、`proxyTarget`、`proxyRewrite`（保留或改写规则的文字说明）、`backendRoute`、`contractSource`、`authMethod`、`authTransport`（header 名或 cookie 名及凭据策略）、`credentialSource`（安全获取途径或配置键）、`platformConstraints`（域名、证书或平台限制说明）。值均为非空字符串；不适用填 `不适用`，未知字段省略，不以空串、示例或推测值代替。仅收集当前端和任务需要的字段；每个已填字段在 `sources` 对象中以同名键记录非空来源说明，说明来自用户确认、文档或配置的具体位置。
- 用户可在执行前按此结构手工预填；开始联调时读取对应项目、应用、环境和端的记录，并与项目实际配置逐项核对。文件不存在或记录不存在时按缺项流程收集，不创建虚构默认值；首次取得确认信息时创建目录和文件。文件仅作本机交接，不改变项目配置；地址即使为非敏感信息也可能属于内部信息，只保存在受控本机，不提交或打进前端产物。密码、令牌、cookie 值、私钥、签名及其他凭据不得写入；已发现敏感值时停止读取和传播，按项目密钥处置流程处理。
用户预填前，在项目根目录运行以下命令打印入口路径；Windows 用户目录用 `USERPROFILE`，其他系统用 `HOME`：

```bash
node -e "const fs=require('fs'),path=require('path'),crypto=require('crypto');let root=fs.realpathSync.native(process.cwd());if(process.platform==='win32')root=root.split(String.fromCharCode(92)).join('/').toLowerCase();const key=crypto.createHash('sha256').update(root,'utf8').digest('hex');const home=process.env.MV_CODING_STANDARDS_HOME||path.join(process.platform==='win32'?process.env.USERPROFILE:process.env.HOME,'.mv','coding-standards');if(!path.isAbsolute(home))throw Error('MV_CODING_STANDARDS_HOME must be absolute');console.log(path.join(home,'integration',key+'.json'));"
```

文件示例（路径与地址仅作字段说明，使用时替换为已确认值）：

```json
{
  "schemaVersion": 1,
  "projectRoot": "/absolute/path/to/project",
  "entries": [{
    "app": ".", "environment": "dev", "platform": "web",
    "values": {"baseUrl": "/api", "proxyTarget": "http://127.0.0.1:8080"},
    "sources": {"baseUrl": "项目配置", "proxyTarget": "用户确认"}
  }]
}
```

- 写回前原子创建同目录的项目键加 .lock 后缀目录作为协作锁，失败则停止；锁内记录随机令牌、主机、进程标识和获取时间，不按年龄自动清理。持锁后重新读取并验证文件，将本次确认时所依据的字段值及对应来源与当前记录逐项对比；字段值或来源发生变化时停止并重新确认，不以旧确认覆盖新记录。只合并本次明确确认的字段和对应来源，保留其他字段、记录与未变更内容；同一定位键不得出现重复记录。更新期间停止其他程序编辑；发布前再次核对原文件摘要，首次创建时确认文件仍不存在，变化则停止。目录、锁目录、临时文件及结果文件仅允许当前用户访问，权限无法确认时停止写入并报告。写入同目录临时文件并校验后原子替换；发布前失败保留原文件，发布后清理失败报告已发布及遗留锁。结束时核对令牌再释放锁；遗留锁须确认原持有者已停止，身份缺失或无法确认时报告并停止。锁只约束遵循本协议的会话，摘要检查不能消除检查后外部写入的竞争；无法确认其他编辑已停止，或文件系统不支持原子创建目录和原子替换时不写入。
- JSON 无法解析、版本不支持、项目路径不匹配、记录键重复、字段类型不符或已填字段缺少来源时，停止使用和写回该文件，报告路径与具体问题并请用户修复；不清空、覆盖、自动迁移或从其他项目借用信息。入口与项目配置冲突的处理遵循上节；确认实际配置需要变更时，单独修改项目配置并重新验证，不能只更新入口后宣称生效。

## 状态管理

- 区分服务端数据（请求缓存）与客户端 UI 状态（表单、开关、选中项）；服务端数据优先由请求层管理，不复制进全局 store。
- 状态提升到最小公共父级即可；可公开分享的状态（页码、非敏感筛选）放 URL，敏感条件与不适合分享的选中状态放受控会话或组件状态。
- 引入全局状态库须有明确理由（跨页面共享的复杂状态），一处创建、明确作用域，不为小型页面引入。

## 错误处理与文案国际化

- 国际化是系统基本要求：文案资源最低双语 `zh-CN`（默认）与 `en-US`，项目初始化即引入双语骨架；新增文案 key 必须两种语言同批补齐，不接受只补中文留空英文。
- locale 载体：项目定义统一的 locale 传递方式（默认 `Accept-Language`）；用户手动切换语言时，前端同步把选择传给后端（覆盖 header 或既定参数），保证接口渲染文案与界面语言一致，不混排。
- 用户可见文案一律走文案资源，不在组件硬编码中文或英文句子；带参数的文案用占位符插值，不拼接句子；硬编码可配 lint 规则（如 eslint-plugin-i18n 类）机器拦截。
- 生成方判据：前端只翻译自己生成的界面文案；系统生成文案与枚举展示名的生成、持久化与渲染判据以本 skill spring-guide「国际化」为唯一全文源，前端默认原样展示译文；项目显式采用 `{key, args}` 即时切换语言契约时按约定渲染，并覆盖未知 key 与参数缺失的兜底。
- 错误码对齐：`code` 走前端文案资源映射通用描述，与后端错误码/i18n 体系对齐，不另造一套错误语义；未收录的错误码走统一兜底并记录原始码；响应中的系统生成 reason 原样展示。
- 表单校验文案同走文案资源；错误边界（Error Boundary）兜底渲染异常，保证局部失败不白屏、不静默吞错，兜底时如实展示可操作的恢复路径。

## 构建与环境变量

- 区分编译期固化与运行时注入：带前端前缀的环境变量（如 `NEXT_PUBLIC_*`、`VITE_*`）会被打进产物——只放无环境差异的公开常量；分环境 API 地址、开关与一切敏感值走运行时注入或相对路径。
- 构建产物不做环境假设：同一产物应可部署到 dev 与 prod（与交付侧「构建期固化」约束同源）；确需编译期差异时在交付说明中显式声明并说明理由。
- 不在提交中携带本地环境文件；`.env*` 保持未跟踪（交付侧预检会拦截被跟踪的 env）。

## 安全基线

- 不将未消毒内容写入 HTML 注入通道（`dangerouslySetInnerHTML` 及框架等价物）；富文本渲染前经 DOMPurify 消毒，不自写过滤器。
- 密钥、内网地址、调试开关、未发布功能开关不进前端包与提交；前端包内容视为完全公开。
- 跳转与嵌 入外部地址用白名单或协议校验，防 `javascript:` 注入；文件下载与预览校验来源。
- 新依赖引入先过 mv-design-standards 的依赖引入评估；锁定文件随变更提交，不手动改锁文件。
- CSP 按实际资源清单配置 `default-src`、`script-src`、`connect-src`、`frame-ancestors` 等来源；脚本优先外部文件或可信 nonce/hash，不为消除报错无条件开放 `unsafe-inline` / `unsafe-eval`。先在测试环境以 Report-Only 收集违例，确认关键页面可用后启用强制策略；记录响应头由应用、反代或托管平台哪一层设置，交付时核对实际 HTTP 响应，不仅检查源码配置。

## 性能基线

- 列表渲染用稳定 key（业务 ID），不用数组下标；大列表用 TanStack Virtual 虚拟化或服务端分页承载，不默认全量渲染。
- 静态资源按框架惯用机制引用（构建管线处理压缩与哈希），不手拼缓存破坏参数；图片按框架提供的组件/指令走懒加载与尺寸约束。
- 依赖以按需引入为默认；引入整包只为一两个工具函数前先核对替代成本。

## 品牌触点接线

- 视觉风格本身（配色、字体、Logo 设计）以设计稿为准，本节只管品牌资产在各触点的接线：新项目初始化时逐项接线，既有项目交付前核对本次涉及的触点，项目不涉及的端或场景按条目判定不适用。
- 标题体系：入口 HTML 默认标题为产品名，路由级标题由路由层统一设置（如「页面名 · 产品名」模板），不在各页面组件零散赋值。
- 图标族：`favicon.ico` 之外配置 SVG 图标与 `apple-touch-icon`（180×180）；图标、Logo 与分享卡图集中存放并经构建管线引用，不在多目录散落副本。
- `<meta name="theme-color">` 取品牌设计令牌中的主题色；暗色模式项目用 `media="(prefers-color-scheme: dark)"` 另配一套。
- 可安装场景（PWA、添加到主屏幕）配置 Web App Manifest：`name`、`short_name`、192/512 图标、`theme_color`、`background_color`、`display`、`start_url`，取值与设计稿一致；不支持安装的端省略本条。
- 公开站点配置分享卡：Open Graph 四项 `og:title`、`og:description`、`og:image`（1200×630）、`og:site_name` 加 Twitter Card `twitter:card`；仅内网使用的端不做分享卡。
- 系统页品牌化：404/403/500/维护页与登录页使用项目 Logo、产品名与版权主体，替换脚手架默认示例内容；首屏加载画面在入口 HTML 内置静态品牌占位（背景色加 Logo），不以脚手架默认样式呈现首屏。
- 页脚：公开站点页脚含版权主体，国内公开站点含 ICP 备案号；后台管理端版权主体按项目约定配置。
- 细节着色走品牌设计令牌：文本选区（`::selection`）、focus ring、滚动条与加载指示器取令牌中的品牌色，不残留脚手架默认色。
- 载体按端：Vite SPA 在 `index.html` 与 `public/`；Next.js 用 Metadata API（`metadata` 导出与 `app/icon.tsx` 一类约定文件）；Taro 在 `app.config.js` 配置全局 `navigationBarTitleText` 与导航栏颜色、逐页覆盖标题，tabBar 图标与选中色用品牌素材，转发经 `useShareAppMessage` 配置标题与分享卡图；小程序名称、头像、简介与隐私弹窗主体名在开放平台控制台维护并列入项目品牌资产清单，不在代码内配置。
- 交付前逐端核对：本次涉及端逐项接线，未接线项在交付说明列明原因；品牌文案（标题模板、分享卡、系统页文案）属用户可见文案，走文案资源双语骨架，不在组件硬编码。

## 格式化与时区

- 日期、数字、货币按当前 locale 用 `Intl` API（`DateTimeFormat`/`NumberFormat`）格式化，不手写格式模板与千分位逻辑。
- 时间显示按后端给的时间戳（UTC 或带时区）转换为用户 locale 展示，不在库、接口或组件里存本地化字符串；跨时区协作的项目显式声明展示时区策略。
- 复数等语法形态用框架 i18n 机制（ICU MessageFormat）表达，不靠拼接句子实现单复数。

## 测试基线

- 业务逻辑（映射、校验、状态流转）与行为改动必须有对应单测；测试断言行为结果而非实现细节（不锁内部函数调用次数一类）；修复缺陷时先补一条能复现该缺陷的测试再修复，测试随产品代码同一变更提交。
- 测试分层、覆盖率口径与测试代码写法统一按本 skill SKILL.md「测试」分节（前端条款见 [frontend-testing.md](frontend-testing.md)）执行；使用项目现有测试框架与脚本，不为规范而更换框架，未实际运行不声称通过。

本文只覆盖前端编码与审查的通用工程条款；技术栈选型、本机调试、构建交付与文档产出分别归对应 skill，视觉风格以项目设计系统为准。
