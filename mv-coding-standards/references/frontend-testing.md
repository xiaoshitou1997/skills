# 前端测试写法

前端测试代码条款，配合本 skill SKILL.md「测试」分节「关键规则」使用；覆盖管理端和用户端网页的 Vite SPA、Next.js，以及用户端 Taro H5/小程序。框架专属编码条款见本 skill「前端 React」分节；与项目已确立测试基线冲突时以项目为准。

## 组件与交互测试（Vitest + Testing Library）

- 测试栈基线 Vitest + Testing Library；沿用项目脚手架既有配置，不为统一而更换。
- 断言行为结果而非实现细节：查渲染输出与用户可感知状态（按钮、文案、禁用态），不锁内部 state、子组件调用次数一类实现细节。
- 三态与分支覆盖：加载、错误、空数据三态，表单校验失败分支，权限分支（有权限/无权限渲染）各有一条交互断言；纯展示组件不强制建测试文件。
- 按页面实际能力验证筛选与分页联动、批量部分成功、导入错误回显、重复提交防护及高危操作确认；覆盖请求超时与权限变化，断言用户可见反馈及数据状态，不假设前端权限控制替代服务端授权。
- 关键交互验证键盘可达、焦点可见及弹层关闭后的焦点返回；在项目支持的代表性视口走查布局与操作可达性，自动测试不能替代真实浏览器和辅助技术检查。
- 用户交互经 Testing Library 的用户事件 API（`userEvent`）触发，不经组件内部方法直调模拟。
- 数据请求经服务层假实现（mock 服务层函数或 MSW 一类请求拦截），不在测试里发真实请求；三态经假实现切换构造。
- 路由与全局状态：路由相关测试用内存路由（TanStack Router 内存 history 等），store 用独立实例注入，不跨用例共享可变单例。

## 业务 E2E（Playwright）

- Web E2E 基线 Playwright，按业务风险选择完整用户旅程；带认证 CRUD 项目默认覆盖登录、核心列表、一条核心写操作、登出。公开站点验证关键浏览与交互；无 UI 的 API / 批处理以对应端到端业务回环验证，不强加登录页或写操作。断言关键业务结果。
- 按业务适用性与风险覆盖替代和异常流程、失败恢复、状态转换、跨系统一致性、重复与并发操作、金额计算及外部副作用，记录场景选择和裁剪依据。真实业务 E2E 连接测试环境中的实际后端服务；全 Mock 场景只能作为隔离测试，不能标记为真实 E2E。
- 发布前执行适用业务 E2E；PR 与提交阶段是否运行按项目管线和变更风险确定。选择器优先业务语义定位（role、文本），不用易碎的样式类名定位。
- 先读取用户指定的测试目标、项目 E2E 配置和测试环境文档，确认测试站点 URL、专用账号的权限和凭据注入方式；缺项向用户询问，不要求在对话中发送密码。目标、账号或实际后端不可用时记录真实联调和对应业务 E2E 未执行、阻塞原因及待补验证，继续不依赖该环境的测试；不指向生产，不复用真实用户账号。

## Taro 端（H5/小程序）

- 单测与组件测试跑在 H5 构建目标上（Vitest + Testing Library），与 Web 端同一套写法；平台差异 API（`Taro.*`）经适配层注入假实现，不在测试内直连真机或开发者工具。
- 小程序原生能力（支付、登录、存储）在测试中用假实现替身；真机走查是发布前人工检查项，不作自动化基线要求。
- 构建产物冒烟：H5 目标经 Playwright 冒烟；小程序目标以「构建成功 + 关键路径真机人工走查」记录证据，不虚构自动化通过。
