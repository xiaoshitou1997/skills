# 镜像构建安全模型（出包与上传侧）

脚本使用调用者或 agent 的权限运行。Skills 提供操作指导与工具，不承担沙箱、授权网关或云端密钥存储的职责。

## 控制措施

1. **最小暴露面**：上传与瘦上下文只含产物与 Dockerfile，秘密暴露面小于源码构建。`.dockerignore` 必须显式排除 `.git` 与 `.env*` 且不得取反包含；这是最低防线，负向规则与其余秘密仍需人工复核。
2. **秘密信息**：项目 `.env.*` 和私钥不得进入上传通道、构建上下文、镜像、Git 或命令日志。上传前对包做密文头检查（端点透明加密环境防线），上传经 SSH 通道，构建点核对 SHA-256 与出包时计算值，不匹配即删除损坏包并中止，不带病构建。
3. **可选扫描策略**：`FF_REQUIRE_SECURITY_SCAN=1` 要求构建时使用 Trivy 扫描镜像，源码扫描另用 Gitleaks；扫描器缺失即失败（fail closed），不能将跳过扫描解释为通过。严格策略应由 CI 落实。
4. **平台控制**：本仓库分发不自动安装命令 Hook；唯一例外是 mv-unattended-watch 的值守 Hook，由用户显式安装。团队控制由 agent 权限、项目 Hook、仓库分支保护和 CI 落实，skill 指令本身不是强制执行机制。
5. **包与镜像常驻的安全理由**：保留包、构建镜像与基础镜像以便审计与回溯构建输入；清理动作一律禁止，存储不足时报告用户请示。

## 边界

部署授权、生产验证与失败恢复规则归 `mv-container-deploy` 的安全模型；本 skill 不写部署收据。对服务器的写操作限于包目录（`~/.mv/image-build/packages/`）与镜像构建，不触碰目标机其他路径。
