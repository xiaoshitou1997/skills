# 非功能性需求采集

开工前把非功能性需求（NFR）提到与功能需求同级的地位确认：规模、网络、部署条件决定系统是否要拆、放哪跑、怎么集成，缺失的功能实现上线即返工。本 skill 只采集与确认画像并标记信号，不做架构决策、不写正式设计文档。

`判定模式 → 采集确认 → 落盘画像 → 放行编码`

- 画像产出为目标项目内文档 `docs/nfr-profile.md`；拆分与部署信号只作为开放问题移交，正式 PRD/HLD 见 `mv-engineering-doc-writer`。
- 画像如何落地为编码决策，条款见 `mv-java-backend-standards`。

## 硬性规范（无例外）

- **画像未确认不放行**：业务编码开工前，目标项目的 NFR 画像必须已确认或全部标注假设；用户明确要求跳过采集时，把风险记录为假设并如实声明，不静默开工。
- **不编造取值**：用户答不上来的项给保守默认并显式请求确认，标「假设」；不用看似合理的数值补全，不静默采用默认值。
- **琐碎改动不触发**：改文案、修注释、代码答疑与审查不进采集流程，不为一行改动追问规模。
- **画像唯一事实源**：已确认的画像以 `docs/nfr-profile.md` 为准，不靠会话记忆；条件变化改文档并记变更，会话口径与文档冲突时以文档为准。

## 非功能性需求与研发影响

每类采集项直接映射到研发决策，并标注信号去向（拆分 / 部署拓扑 / 集成方式 / 编码）：

| 类目 | 采集要点 | 对研发的影响 |
| --- | --- | --- |
| 规模与容量 | 用户规模、在线量、TPS/QPS、峰值突发 | 并发控制、锁粒度、限流降级、缓存、扩展假设（编码） |
| 依赖与调用画像 | 每个外部系统：方向、频率与峰值；频率差数量级单独标注 | 高频集成走缓存/批量/连接复用，低频裸调；频率差数量级叠加部署约束不同，提示独立部署单元（拆分信号） |
| 网络环境 | 网络平面、连通性归属（我方/对方/第三方）、时延 | 组件放置受平面限制；跨不受控网络的集成被迫异步化与缓冲，可用性边界不由我方定（部署拓扑 + 集成方式） |
| 部署环境 | 载体（虚拟机/容器/物理机）、可部署位置、管控方、资源约束 | 部署拓扑、配置与容量设计；位置不自由时按平面适配拆分（部署拓扑） |
| 数据量与增长 | 现量、增速、留存与归档要求 | 分页、索引、批处理、归档；增长曲线决定分库分表信号（编码 + 拆分信号） |
| 关键业务流程 | 核心链路、资金与状态类操作 | 事务边界、幂等、失败补偿、对账（编码） |
| 可用性与降级 | 目标可用性、可容忍降级方式、恢复时限 | 超时、重试、熔断、队列缓冲、监控维度（编码 + 部署拓扑） |
| 安全与合规基线 | 鉴权、审计、数据保护要求 | 鉴权与审计设计（编码；超出采集深度的安全细则列入开放问题移交） |

典型信号示例：系统 A 对接外部系统 1/2/3，三者网络平面不同、调用频率差数量级、连通性不归我方——功能需求不变，画像即提示按集成线拆分部署单元，而不是在单体内堆防御式代码。

## 工作流

1. 判定模式：新项目/新模块 → 全量采集；日常新需求开工 → 读目标项目 `docs/nfr-profile.md`，缺哪项补哪项；画像已齐备且本次需求无新增触碰项（如新外部依赖、新数据源、新部署位置）时直接放行进编码，放行结论记「无新增触碰」；有新增触碰项按缺项补采；改文案、修注释、答疑审查跳过。
2. 采集确认：按类目逐项向用户提问，一轮问完，不为缺失细节反复追问；能答 → 记「已确认」；答不上 → 按保守默认基准给出建议值，显式请求确认，记「假设」。
3. 落盘画像：按 [references/nfr-profile-template.md](references/nfr-profile-template.md) 写或更新 `docs/nfr-profile.md`，每项带 已确认/假设 状态与日期，追加变更记录；文档缺失时新建并纳入版本管理。
4. 应用与放行：放行前核对画像无未决项；拆分与部署信号以开放问题列出移交用户与 HLD，不代做架构决策；实现期按画像映射编码决策，条款见 `mv-java-backend-standards`。

## 保守默认基准

用户答不上来时的下限建议，保守但不越界过度设计：

- 写操作默认设计为幂等；跨系统调用默认带超时与明确失败路径。
- 列表与查询默认分页，禁止按无界结果集编码。
- 并发容量未知时预留限流与配置化扩展点，不把吞吐假设硬编码进实现。
- 跨不受控网络的集成默认可异步、可降级、可对账，不做强同步依赖。
- 数据量未知时索引与分页按会增长设计，不按当前量优化到极限。

## 输出

产出与更新 `docs/nfr-profile.md`（含状态与变更记录）；采集结论一次说清：本次需求触碰的画像项（无则记「无新增触碰」）、已确认项、假设项（含建议值与待确认原因）、放行或拦截结论；拆分与部署信号列为开放问题，不混入功能实现说明。

## 边界

正式 PRD/HLD 写作归 mv-engineering-doc-writer，画像与开放问题可作为其输入；编码健壮性条款见 mv-java-backend-standards；画像引出的技术选型与基线归 mv-tech-stack-standards；出包与镜像构建见 mv-image-build，部署晋级回滚归 mv-container-deploy。
