# 非功能性需求采集

开工前把非功能性需求（NFR）提到与功能需求同级的地位确认：规模、网络、部署条件决定系统是否要拆、放哪跑、怎么集成，缺失的功能实现上线即返工。本 skill 只采集与确认画像并标记信号，不做架构决策、不写正式设计文档。

`判定模式 → 采集确认 → 落盘画像 → 放行编码`

- 画像产出为目标项目内文档 `docs/nfr-profile.md`；拆分与部署信号只作为开放问题移交，正式 PRD/HLD 见 `mv-engineering-doc-writer`。
- 画像如何落地为编码决策，条款见 `mv-java-backend-standards`。

## 硬性规范（无例外）

- **画像未确认不放行**：业务编码开工前，适用画像项必须是已确认事实，或仍标「假设」且已记录用户同意采用的范围与日期；仅标假设、未获采用确认不放行；已同意采用的假设超过记录的复核时点或失效条件未复核的，同样不放行。用户明确授权跳过采集是例外：记录授权范围、日期、缺项与风险，可在该范围内继续；缺项仍为未知或假设，不改成已确认事实。
- **不编造取值**：用户答不上来的项按保守默认基准提出处理建议，显式请求同意采用，并保留「假设」属性；容量等数值未知时记 `TBD`，不用看似合理的取值补全，不静默采用默认值。
- **琐碎改动不触发**：改文案、修注释、代码答疑与审查不进采集流程，不为一行改动追问规模。
- **画像唯一事实源**：已确认的画像以 `docs/nfr-profile.md` 为准，不靠会话记忆；条件变化改文档并记变更，会话口径与文档冲突时以文档为准。

## 非功能性需求与研发影响

每类采集项直接映射到研发决策，并标注信号去向（拆分 / 部署拓扑 / 集成方式 / 编码）：

| 类目 | 采集要点 | 对研发的影响 |
| --- | --- | --- |
| 规模与容量 | 用户规模、在线量、TPS/QPS、峰值突发及其时段与诱因、核心接口延迟目标（适用时采：渠道形态、租户隔离形态） | 并发控制、锁粒度、限流降级、缓存、扩展假设（编码） |
| 依赖与调用画像 | 每个外部系统：方向、频率与峰值；频率差数量级单独标注；对方 SLA/配额/对我方限流等反向约束；数据归属与一致性语义（以谁为准、同步时效） | 高频集成走缓存/批量/连接复用，低频裸调；反向约束封顶我方可达吞吐；数据归属与一致性语义决定同步与对账设计；频率差数量级叠加部署约束不同，提示独立部署单元（拆分信号） |
| 网络环境 | 网络平面、连通性归属（我方/对方/第三方）、时延 | 组件放置受平面限制；跨不受控网络的集成被迫异步化与缓冲，可用性边界不由我方定（部署拓扑 + 集成方式） |
| 部署环境 | 载体（虚拟机/容器/物理机）、可部署位置、管控方、资源约束（适用时采：数据存放地域与出境约束） | 部署拓扑、配置与容量设计；位置不自由时按平面适配拆分（部署拓扑） |
| 数据量与增长 | 现量、增速、留存与归档要求、文件与对象存储量及留存（适用时采：存量切换窗口与并行期） | 分页、索引、批处理、归档与大表 DDL 执行策略；增长曲线决定分库分表信号（编码 + 拆分信号） |
| 关键业务流程 | 核心链路、资金与状态类操作 | 事务边界、幂等、失败补偿、对账（编码） |
| 可用性与降级 | 目标可用性、可容忍降级方式、恢复时限、数据丢失容忍（RPO）与备份要求、停机维护窗口与升级方式（滚动/灰度约束） | 超时、重试、熔断、队列缓冲、监控维度、备份与恢复设计（编码 + 部署拓扑） |
| 安全与合规基线 | 鉴权、审计、数据保护要求 | 鉴权与审计设计（编码；超出采集深度的安全细则列入开放问题移交） |

典型信号示例：系统 A 对接外部系统 1/2/3，三者网络平面不同、调用频率差数量级、连通性不归我方——功能需求不变，画像即提示按集成线拆分部署单元，而不是在单体内堆防御式代码。

## 工作流

1. 判定模式：新项目/新模块 → 全量采集；日常新需求开工 → 读目标项目 `docs/nfr-profile.md`，缺哪项补哪项。画像适用项满足放行条件且本次需求无新增触碰项（如新外部依赖、新数据源、新部署位置）时，复用事实与已获采用确认的假设，结论记「无新增触碰」；有新增触碰项按缺项补采；改文案、修注释、答疑审查跳过。
2. 采集确认：按类目逐项向用户提问，一次一问；能确认的事实记「已确认」，答不上来的项提出保守处理建议并记「假设」，单独记录采用确认「待确认/已同意/未同意」、适用范围、日期，已同意时一并记录复核时点或失效条件。用户同意采用不把假设升级为事实。
3. 落盘画像：按 [references/nfr-profile-template.md](references/nfr-profile-template.md) 写或更新 `docs/nfr-profile.md`，记录事实状态、证据或来源、假设采用确认及日期，追加变更记录；文档缺失时新建并纳入版本管理。明确授权跳过采集时另记授权及遗留缺项，不填造取值。
4. 应用与放行：逐项核对事实已确认，或假设已获用户同意采用且未超过记录的复核时点或失效条件，未满足项拦截业务编码；明确跳过采集授权时仅在授权范围内放行并声明风险。拆分与部署信号以开放问题列出移交用户与 HLD，不代做架构决策；实现期按画像映射编码决策，条款见 `mv-java-backend-standards`。

## 保守默认基准

用户答不上来时的下限建议，保守但不越界过度设计：

- 写操作默认设计为幂等；跨系统调用默认带超时与明确失败路径。
- 列表与查询默认分页，禁止按无界结果集编码。
- 并发容量未知时预留限流与配置化扩展点，不把吞吐假设硬编码进实现。
- 跨不受控网络的集成默认可异步、可降级、可对账，不做强同步依赖。
- 数据量未知时索引与分页按会增长设计，不按当前量优化到极限。

## 输出

产出与更新 `docs/nfr-profile.md`（含状态、假设采用确认与变更记录）；采集结论一次说清：本次需求触碰的画像项（无则记「无新增触碰」）、已确认事实、假设项及采用确认、缺项与放行或拦截依据。跳过采集时列明用户授权范围与风险；拆分与部署信号列为开放问题，不混入功能实现说明。

## 边界

正式 PRD/HLD 写作归 mv-engineering-doc-writer，画像与开放问题可作为其输入；编码健壮性条款见 mv-java-backend-standards；画像引出的技术选型与基线归 mv-tech-stack-standards；出包与镜像构建见 mv-image-build，部署晋级回滚归 mv-container-deploy，宿主直启调试见 mv-local-debug。
