# 项目上下文

适用于新项目需求分析、存量接管与涉及业务边界的变更。用户明确需求与项目已确认约定优先于团队默认；本表是读取和补齐上下文的提示，不要求每次新建一份文件。

## 上下文读取

1. 先读项目入口说明、当前任务与已有需求，再读相关契约、ADR、测试和环境说明；连接的平台已含资料时优先读取，不要求重复口述。
2. 记录项目资料的版本或更新时间；文档、工单与代码冲突时分别标明「已确认要求」与「当前实现」，由对应责任方确认差异。
3. 只提取当前任务有关的信息；业务事实、团队默认与环境配置分别记录在各自来源，不整份复制其他项目的模板。

| 信息 | 记录内容 | 归属 |
| --- | --- | --- |
| 业务 | 行业、目标、领域术语、角色、流程、业务规则与验收方 | 当前项目需求、工单或 PRD |
| 范围 | 当前交付、排除项、外部系统及责任边界 | 当前项目需求或版本范围 |
| 技术 | 现有栈与版本、仓库布局、契约、已采纳 ADR、基线偏离 | 当前项目 README、构建配置与 ADR |
| 环境 | 开发拓扑、目标环境、连接参数引用、交付与恢复约束 | 当前项目环境说明与未跟踪配置；不复制凭据值 |
| 质量 | 数据敏感级别、容量、性能、可用性、RPO/RTO 与适用法规依据 | 当前项目质量要求；无依据的数值标待确认 |
| 验证 | 已执行检查、对应版本与环境、未验证项 | 项目测试记录与交付证据 |

## 团队默认与项目事实

- 团队默认技术栈、模块命名与研发规范可以跨项目复用；行业业务对象、状态机、权限矩阵、数据口径与客户承诺来自当前项目。
- Redis、RabbitMQ、对象存储及各前端端型按已确认能力引入；团队有选型基线不意味着每个项目必须初始化所有组件。
- 示例使用某个行业只为解释方法，复制前替换为当前领域术语并重新核对规则。
- 团队提供的开发连接默认值仍需在执行环境核验可达性；宿主回环地址不能直接当作远端服务器或容器中的同一服务地址。

## 存量接管

1. 记录当前版本、可运行入口、数据模型与实际发布路径；保留项目已采纳的技术和接口约定。
2. 选择一条与本次任务相关的业务主流程，核对需求、代码、接口和已有测试；行为不一致处列为差异，不直接按团队模板改造。
3. 先记录可重复的现状验证，再设计变更后的验收；历史缺陷、明确要求与候选改进分开列出。
4. 技术栈迁移、模块重划或平台替换是独立决策；只有本次目标需要时才扩展范围，并交对应规范评估。

本文件只定义项目上下文的取得与使用方式；具体技术和环境操作由对应 skill 执行。
