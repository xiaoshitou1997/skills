# ADR 模板与填写要求

架构决策记录（ADR）用于留存影响面跨模块、不可逆或存在多个可行备选的决策。一项决策一份，编号连续，文件放项目 `docs/adr/` 或项目既定位置。

## 模板

```markdown
# ADR-<编号>：<决策标题>

- 状态：提议 / 已接受 / 已废弃 / 被取代（被取代时写 ADR 编号）
- 日期：YYYY-MM-DD
- 决策人：
- 关联需求 / 文档：

## 背景

<业务目标、约束、现状与问题；只写决策所需事实。>

## 决策

<选定的方案、边界与关键参数；写可执行的结论，不写讨论过程。>

## 备选方案

| 方案 | 优点 | 代价 / 风险 | 放弃原因 |
| --- | --- | --- | --- |
|  |  |  |  |

## 影响

<涉及模块/服务/数据/团队；兼容性、迁移、成本与运维影响。>

## 回滚与失效条件

<如何回退；什么条件下重新评估。>

## 开放问题

<未决事项、责任人、截止时间；没有则写「无」。>
```

## 填写要求

- 背景只写事实与约束，不写「经过讨论」类过程；讨论记录不进 ADR。
- 决策写选定方案与边界；参数、版本、协议名保留原文。
- 备选方案至少列一个真实可选项；没有备选时说明约束。
- 影响必须覆盖数据迁移、兼容性、回滚与成本；不可回滚的决策显式标注。
- 状态变更用新 ADR 取代旧 ADR，不直接改写已接受 ADR 的决策内容。
- 技术栈选型的 ADR 同样用本模板；版本基线与选型要点见本 skill「架构与选型」的技术栈基线。

模板不替代 HLD/LLD；文档结构见本 skill「工程文档与图件」。
