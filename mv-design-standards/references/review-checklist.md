# 架构评审清单

评审对象是新系统方案、重大变更或既有系统架构整改。逐项给出结论：通过 / 有风险 / 不通过；有风险的写明影响与整改期限。评审不替代安全评审与代码审查。

## 边界与依赖

- [ ] 系统/模块边界与业务能力对应，职责能用一句话说清。
- [ ] 依赖方向单向，无循环依赖；领域层不依赖接入层或具体 Web 框架。
- [ ] 跨边界只经接口或事件；没有跨模块直接读表、共享可变状态。
- [ ] 共享库只放通用设施，不放业务规则；没有「上帝模块」。

## 数据

- [ ] 每个数据有明确所有者；写入口唯一，读路径清楚。
- [ ] 跨服务一致性方案明确（本地事务 / Outbox / Saga / 对账），延迟与失败可见。
- [ ] 报表、检索、导出有查询边界与负载评估；影响在线事务时隔离读模型，并说明同步延迟。
- [ ] 数据保留、归档、删除与迁移方案明确；不可逆操作有备份与回滚。

## 失败与容量

- [ ] 外部调用有超时、重试、熔断、限流；非幂等操作不自动重试。
- [ ] 异步链路有幂等、死信、积压告警与人工介入路径。
- [ ] 关键路径有容量估算与降级方案；单点与故障域已识别。
- [ ] 启动依赖、缓存/MQ 不可用时的行为明确，不因依赖宕机整体不可用。

## 安全与租户

- [ ] 信任边界与外部暴露面清楚；管理面与业务面按项目形态划分，认证和授权分别校验。
- [ ] 多数双端项目已核对共用 service/web；C 端双端产品已核对独立工程、入口及部署单元，偏离默认时有项目事实与影响记录。
- [ ] 认证、授权、对象级归属校验覆盖所有入口；无前端隐藏代替后端授权。
- [ ] 多租户场景的租户上下文、查询过滤、唯一约束与跨租户管理已设计。
- [ ] 敏感数据分级、脱敏、加密与日志禁打已覆盖；安全评审按 mv-security-standards 执行。

## 可观测与运维

- [ ] 日志、指标、追踪覆盖关键链路与集成点；告警有判据与处置动作。
- [ ] 部署拓扑、配置与凭据注入方式明确；生产变更可回滚。
- [ ] 成本（资源、存储、流量、第三方调用）有估算与上限。

## 演进与团队

- [ ] 方案可按批次发布，每批可独立回滚；没有不可拆的大爆炸迁移。
- [ ] 接口与数据变更兼容旧版本；旧系统下线有流量切换与观察期。
- [ ] 归属团队、值班与运维责任明确；没有「建完没人管」的组件。

## 输出

评审记录写：结论、风险清单（影响/概率/整改期限/责任人）、开放问题、需要回填 ADR 或 HLD/LLD 的条目。未执行的检查写「未执行」，不写「通过」。

本文只管架构评审的组织与判据；安全评审归 mv-security-standards，文档格式见本 skill「工程文档与图件」。
