# 基线模板与选型记录

适用于将团队技术基线落为当前项目的选型记录。团队默认值以 SKILL.md 为唯一来源；本表记录项目采纳结果，不重复维护另一份团队基线。

## 项目基线记录

| 类别 | 项目选定值 | 版本锁定方式 | 与团队基线的关系 |
| --- | --- | --- | --- |
| 语言运行时 | 按实际栈填写 | 如 `.java-version`、`engines` | 采纳 / 存量保留 / 偏离及 ADR |
| 后端框架 | 有后端时填写 | 如 parent BOM、version catalog | 同上 |
| 持久层 | 有持久化时填写 | 依赖管理 | 同上 |
| 构建工具 | 按模块填写 | wrapper 优先 | 同上 |
| 数据库 | 需要时填写 | 固定版本与迁移记录 | 同上 |
| 中间件 | 按需列出 | 固定版本与项目配置 | 同上 |

## 填写与维护

1. 先读取项目构建文件、版本管理文件和既有 ADR，逐模块记录实际依赖与版本；新项目按已确认范围从团队基线选择，只为需要的类别填表。
2. 每行记录项目实际采用的值、精确版本或项目声明的版本范围、版本来源文件和锁定方式；无法从项目取得的版本标记待确认，不推断为团队当前版本。
3. 对偏离基线或新增基线未覆盖类别，记录需求约束、候选方案、比较依据、最终选择、影响及退出方式，并链接对应 ADR；沿用存量方案时记录现状，不自动发起升级。
4. 将记录保存到项目已有技术基线或 ADR 位置；位置不存在时询问项目约定。变更依赖或版本后同步更新对应行，以构建配置和锁文件核对，验证命令与结果写入变更交付说明。

## 选型决策要点

- 团队熟悉度与现有项目一致性优先于社区热度；引入第二套同类栈需说明迁移与共存成本。
- 运维能力匹配：无对应运维经验时不选需要专职维护的组件；托管服务优先评估。
- 社区活跃度与维护状态：近期有发布、issue 有响应、无已知未修复安全漏洞。
- License 与合规：进生产前核对 License 兼容性与团队合规要求。
- 退出成本：评估数据、代码与流程的迁移代价，优先存在替代方案的选型。

## ADR

选型决策需要留痕时，按本 skill 的 ADR 模板（references/adr-template.md）编写；本文件只保留基线与选型要点，不维护第二份模板。
