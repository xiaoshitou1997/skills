# Java 后端规范

## 作用与优先级

这是**规范型 Skill**，在 Agent 编码、审查、测试期间引用；不负责编排 Spec/Plan/Tasks，不直接启动、Commit 或部署。适用于 Java 后端项目：通用条款对任意 Java 后端框架适用，Spring Boot 与 JPA 专属条款仅在使用对应框架时应用，不向其他框架强加不兼容约束。

优先级：用户明确需求和项目已正式采纳的规范 / ADR → 本规范 → 框架默认约定。

## 开始前确认

开始前确认本次业务范围、需求来源、版本及优先级，不默认原型、旧文档或现有代码永远权威。代码用于说明当前实现；与已确认需求不一致时记录差距，不反向改写需求。涉及表或接口设计先核对当前 DDL、迁移与契约基线，保留必要语义增量，避免并行修改覆盖彼此决策。新需求开工且规模、网络、部署等非功能性约束未确认时，先与用户确认这些约束，再按本规范实施。

## 关键规则

1. `Controller` 处理路由、校验、协议映射，不编写核心业务逻辑，不直接操作数据访问层。
2. `Service` 处理业务/事务；`Mapper`/`Repository` 处理数据库持久化。
3. 分层以项目实际边界为准，不形式化地给所有简单逻辑强加接口与实现类。
4. 命名语义明确：类与方法 camelCase/PascalCase，数据库字段 snake_case。
5. 命名按英文习惯表达语义，不做中文直译：布尔判断用 `isNormal` 一类 is/has/can 命名，不写 `judgeIfNormal`。
6. DTO/VO/API Contract 不直接泄露持久层 Entity。
7. 按项目既有 API 响应契约返回数据，不擅自把所有接口改为新的 `ApiResponse`。
8. 项目无既有响应契约时按基线统一包络（`code`/`message`/`data`，见 mv-tech-stack-baseline），不临时发明新包络。
9. 输入校验用 Bean Validation，保证客户端看到明确错误码和不暴露内部异常。
10. 捕获异常必须有实际处理意图，不吞异常，不用 `printStackTrace()`。
11. 异步任务、批处理和后台作业必须正确传播或记录失败状态，不把「请求已接受」或「没有异常抛出」当成执行成功。
12. 日志采用 SLF4J 参数化占位符，不使用 System.out。
13. 不重复记录同一 stacktrace，不泄露 Token/密码/PII 或全量请求体。
14. 禁止无界全表列表，列表查询必须有分页或数量上限。
15. 消除循环单行查询（N+1），改用批量取数或关联查询。
16. SQL 使用参数绑定，不拼接 SQL 字符串。
17. 查询字段按需选取，不在生产代码里使用 `SELECT *` 作为默认查询模式。
18. 新增或修改查询时核对索引、事务、幂等与并发安全。
19. 事务置于真实业务边界，理解所用框架的事务代理与自调用行为。
20. 事务内不做网络 IO 或长时间等待。
21. `rollbackFor = Exception.class` 在业务需要时指定，不假设每个事务都必须模板式声明。
22. 配置与 Secret 分离：敏感信息经运行时环境变量或 Secret Store 注入，不硬编码密钥。
23. `.env.prod` 等生产配置不提交 Git。
24. 配置支持按 profile 环境差异化。
25. 业务逻辑与行为改动必须写单元测试，高风险逻辑另加必要的集成测试。
26. 测试覆盖正常路径、边界条件、异常和并发/事务场景。
27. 使用项目现有 JUnit/Mockito/Testcontainers 等工具，不为规范而更换框架。
28. 改动现有系统时保持最小必要变更，优先遵从项目已有模块、依赖版本与兼容性约束。
29. 不引入未使用的 import，新产生的多余 import、代码块与类一律删除。
30. 涉及契约、数据库、升级或不兼容 API 时更新对应文档和迁移建议。
31. 集成组件封装鉴权、协议包络、超时等技术机制，业务侧保留业务接口与决策。
32. 优先使用现有客户端的声明能力，不为复用另造通用路径调用门面或代理栈。
33. 只实现组件的任务，不自动扩展成服务接线与业务编排。
34. 外部接口响应、MQ 消息、第三方回调与导入数据先校验结构、取值与来源再使用。
35. 校验不过按业务失败处理并记日志，不静默降级。
36. 外部返回的成功标志不替代本方执行结果的确认。
37. 外部传入的标识与取值不直接用作授权、资金等敏感决策依据。
38. 角色与权限采用 RBAC 模型。
39. 权限校验在入口层统一实现（声明式注解或集中拦截器），不在业务代码内逐个手写判断。
40. 权限点按业务操作定义且前后端共用同一权限标识：前端列表页面与后端列表接口是同一个权限，前端删除按钮与后端删除接口是同一个权限，不拆开设计。
41. 权限点与菜单等结构定义是版本化种子数据，不设运行时管理入口，运行时只管理角色及其授予关系。
42. 状态、类型、角色等枚举型字段用 Java 枚举全链路承载（存储、入参、返回值、判断），不以 String 中转。
43. 枚举落库映射按项目持久层框架确立，同一项目不混用。
44. 每个独立业务失败场景对应唯一错误码枚举，不复用既有错误码扩展语义。
45. 用户可见文案走国际化资源，不在业务代码硬编码。
46. 国际化最低支持双语 `zh-CN`（默认）与 `en-US`，从首个接口起落地，不接受「先中文后补英文」。
47. 系统生成的描述性文案（原因、备注、通知、导出内容）由后端在生成时按目标 locale 输出译文，不以 messageKey 交前端二次翻译，载体与判据见 spring-guide「国际化」。
48. 结构化业务数据用强类型 POJO 承载，不用 Map/JsonNode 替代。
49. 项目已有错误码/文案体系优先。
50. 线程池用 `ThreadPoolExecutor` 显式建池。
51. `ThreadLocal` 用后 remove。
52. foreach 中不增删元素。
53. 遍历 Map 用 entrySet。
54. 返回集合不返回 null。
55. 判空统一走标准工具类。
56. 每个新增配置项必须先在配置文件定义（格式优先 YAML，如 `application.yml`），不在代码中定义默认值。
57. 环境变量覆盖默认走宽松绑定：点换下划线、去连字符、转大写（`app.jwt.secret` → `APP_JWT_SECRET`）。
58. 含连字符的 key 转换后丢失词界（`expire-minutes` → `EXPIREMINUTES`），此类配置项须在配置文件用属性占位符显式声明环境变量与默认值（`expire-minutes: ${APP_JWT_EXPIRE_MINUTES:30}`）。
59. 注入用 `@ConfigurationProperties` 类型化绑定，禁止 `@Value` 注入。
60. 枚举持久化用 `@Enumerated(EnumType.STRING)` 保证存储值可读；同一项目不混用映射方案；映射变更涉及历史数据与兼容性，作为独立迁移评估。
61. 查询按需取字段：列表与报表场景用投影（DTO projection）替代实体全字段查询，即 `SELECT *` 的同等约束。
62. 关联加载显式化：需要关联数据时用 fetch join 或 `@EntityGraph` 明确获取路径，默认保持懒加载，避免在事务外触发懒加载异常；此为默认行为，可按项目既有取数风格覆盖。

## 输出

1. 交付前按 java-guide「交付自查清单」逐项核对本次变更直接影响范围；未修改代码不追溯达标，兼容性未应用条款与历史问题分别如实报告。
2. 按「自动验证与边界」执行 `scripts/quality-check.sh quick`，项目已有等价检查时优先项目检查并说明。
3. 交付说明列出关键规范决策、针对本次变更的遵循/偏离原因、实际应用的框架条款与验证结果；未执行的检查明确写「未执行」，不虚构通过。

## 自动验证与边界

本规范是项目规范的补充，供支持 Agent Skills 的编码助手编码、自检与审查时引用。优先运行项目已有检查；交付前执行本 skill 的 `scripts/quality-check.sh quick`，深入验证用 `full`。该脚本执行项目级检查；需要模块或测试范围验证时直接使用项目已有命令，并报告验证范围与既有失败，不因脚本缺少范围参数扩大整改。从加载的 SKILL.md 定位脚本绝对路径，保持用户项目为工作目录。静态规范和自动检查不能互相替代。
