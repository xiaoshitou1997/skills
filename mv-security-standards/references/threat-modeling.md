# 威胁建模

适用于新系统、新入口（登录、开放 API、回调、文件上传、管理端）、新数据流与重大变更。目标是识别信任边界与威胁，给每条威胁一个控制措施或明确的风险接受，不追求穷举。

## 步骤

1. 画数据流：用户/角色 → 入口 → 服务 → 数据存储 → 外部系统；标出跨越信任边界的位置。
2. 标资产：账号、令牌、个人信息、业务数据、资金/交易、配置与密钥、审计日志。
3. 识别威胁：按 STRIDE 逐类过一遍（伪造、篡改、否认、信息泄露、拒绝服务、权限提升）；结合入口与数据流写具体场景，不写术语堆砌。
4. 定控制：每条威胁写预防、检测、响应三层措施；无可行控制的写风险接受理由、责任人与复核日期。
5. 回填：威胁模型结论进入 HLD/LLD 的安全章节与 ADR；新增入口或数据流时更新。

## 常见盲区

- 只审外部入口，不审服务间调用、管理端、定时任务与消息消费。
- 只审认证，不审对象级授权（IDOR）与租户隔离。
- 只审应用，不审依赖、构建链、镜像与配置。
- 把「内网」当作信任理由；内网横向移动与供应链攻击同样在范围内。

威胁模型是设计输入；具体认证授权实现归 mv-backend-standards，前端安全实现归 mv-frontend-standards。
