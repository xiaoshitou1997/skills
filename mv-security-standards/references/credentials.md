# 凭据与密钥管理

适用于应用密钥、数据库口令、API Key、JWT 签名密钥、SSH 私钥、CI/CD 凭据与第三方回调密钥。目标是凭据不泄露、可轮换、可追溯。

## 规则

1. **不进版本控制**：真实凭据不进 Git、镜像、构建上下文、日志、错误信息与截图；样例文件只放占位值。
2. **按环境隔离**：dev/prod 使用不同凭据；生产凭据不下发到开发机；个人账号不共用。
3. **最小权限**：应用账号只授予所需库/表/操作；第三方 API Key 按最小 scope；管理凭据与业务凭据分开。
4. **注入方式**：运行时环境变量或 secrets manager；不把密钥写入代码默认值；容器编排的注入规则见 mv-orchestration-standards。
5. **轮换**：JWT 签名密钥、数据库口令、第三方 Key 有轮换周期与双钥过渡方案；离职与泄露事件立即轮换。
6. **存储**：服务端存储只存不可逆散列（密码）或加密后的密文；不存可逆明文；比较用恒定时间算法。
7. **使用**：不把凭据拼进 URL；不在前端包中出现；不在日志打印；调试输出前先脱敏。
8. **检测**：提交前与 CI 用 Gitleaks 一类扫描；发现疑似泄露立即停止提交、轮换并排查使用记录；扫描器缺失如实报告，不宣称通过。

## 轮换检查

- [ ] 新凭据已生成并验证可用。
- [ ] 双钥/双口令过渡期内新旧均可验证。
- [ ] 旧凭据在确认无流量后吊销。
- [ ] 使用方配置已更新，回滚路径明确。
- [ ] 轮换记录写入运维记录。

凭据的生成命令与编排注入细节归 mv-orchestration-standards；交付链路中的上传与部署凭据控制归 mv-image-builder 与 mv-container-deploy。
