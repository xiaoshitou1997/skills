# 依赖与供应链安全

适用于新增依赖、升级版本、引入第三方 SDK、基础镜像与构建工具。目标是把漏洞与供应链风险控制在可发现、可处置、可追溯的范围内。

## 引入

- 新依赖先过 mv-tech-stack-baseline 的依赖引入评估：维护状态、License、安全记录、退出成本。
- 优先复用已有库能力；不为一个小功能引入大型框架。
- 锁定版本：使用 BOM/version catalog/lockfile；不散落单点版本；构建可复现。
- 第三方 SDK 默认不引，优先协议直连 + 自封装；行业事实标准客户端（S3、SFTP、SMTP 等）例外。

## 扫描

- 源码与依赖：OWASP dependency-check、npm audit/pnpm audit、Gitleaks 等按项目栈选择；CI 中固定执行。
- 镜像：Trivy 扫描基础镜像与构建产物；基础镜像固定版本并定期重建。
- 扫描器缺失或无法联网时如实报告「未执行」，不把跳过当通过；将缺失的检查、影响和风险交项目发布责任人判断，项目强制门禁未满足时停止发布。

## 处置

| 级别 | 默认处置 |
| --- | --- |
| Critical | 立即评估；可利用且有修复版本时阻断发布并安排紧急升级 |
| High | 在约定窗口内升级或缓解；无修复版本时记录补偿控制与复核日期 |
| Medium / Low | 纳入例行升级；结合可达性评估 |

- 漏洞记录：组件、版本、CVE、可达性、影响、处置、责任人、复核日期。
- 未修复的 High/Critical 在发布前记录影响、可达性、补偿控制（WAF、网络隔离、功能禁用）、责任人和复核日期；项目发布责任人明确接受剩余风险，项目策略更严格时从其规定。不能满足阻断条件的整改或例外要求时停止发布，不静默接受。
- 基础镜像 EOL 后不继续使用；确需延续时登记理由与评估日期。

## 构建链

- 构建依赖锁定；不使用来源不明的脚本与二进制；下载校验发行方校验和或签名。
- CI 凭据最小权限；构建产物带 commit 溯源；发布包与镜像可追溯到构建输入。
- 依赖升级按 mv-tech-stack-baseline 的升级流程执行，不搭车业务变更。

本文只管供应链安全控制；版本基线与选型归 mv-tech-stack-baseline，镜像构建流程归 mv-image-builder。
