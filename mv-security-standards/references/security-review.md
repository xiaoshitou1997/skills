# 安全评审与安全测试

用于上线前安全评审、重大变更评审与周期性安全自查。评审结论写「通过 / 有条件通过 / 不通过」，有条件通过与不通过必须列整改项、责任人与期限。

## 评审清单

### 入口与身份

- [ ] 所有入口已盘点：Web、API、管理端、回调、文件上传、消息消费、定时任务。
- [ ] 认证覆盖所有非公开入口；服务间调用有身份与鉴权，不依赖网络位置。
- [ ] 会话与令牌：短期 access、可吊销 refresh、HttpOnly/Secure、登出与失效生效。
- [ ] 密码策略、失败锁定/限流、防账号枚举；多因素按合规要求。

### 授权

- [ ] 权限点按业务操作定义，前后端共用同一标识；入口层统一校验。
- [ ] 对象级授权：每次按资源归属校验，防 IDOR；不信任客户端传入的用户/租户 ID。
- [ ] 管理端与业务端权限分离；高危操作有二次确认与审计。
- [ ] 多租户：租户上下文不可由客户端篡改；查询、唯一约束、导出、后台任务均隔离。

### 数据

- [ ] 数据分级清单完整；敏感字段采集最小化、展示脱敏、传输/存储加密。
- [ ] 日志、错误、监控、导出不含秘密与完整敏感数据。
- [ ] 留存与删除策略明确；测试数据脱敏。
- [ ] 备份加密与访问控制；恢复演练覆盖权限。

### 输入、输出与依赖

- [ ] 服务端校验所有外部输入；SQL 参数化；输出按上下文编码。
- [ ] 文件上传限制类型/大小/存储位置；下载防路径穿越。
- [ ] SSRF、XXE、反序列化、命令注入、开放重定向已评估。
- [ ] 依赖与镜像漏洞扫描已执行；高危有处置或补偿控制。
- [ ] 安全响应头、CSP、CORS 按前端部署形态配置（前端细则归 mv-frontend-standards）。

### 失败与审计

- [ ] 认证/授权/校验失败默认拒绝，不降级到宽松路径。
- [ ] 异常不泄露堆栈、SQL、内部地址；限流与防爆破生效。
- [ ] 登录、授权失败、敏感操作、管理操作有审计；审计日志防篡改并留存。
- [ ] 漏洞与事件响应流程明确；安全事件按 mv-ops-standards 的事故响应执行。

## 安全测试

| 类型 | 覆盖 | 证据 |
| --- | --- | --- |
| 认证/授权用例 | 未登录、越权、对象级越权、租户越权、角色边界 | 用例与结果 |
| 注入与输入 | SQL/命令/模板/表达式注入、文件上传、SSRF/XXE | 用例或扫描报告 |
| 敏感信息 | 日志、错误、响应、导出、前端包 | 抽查记录 |
| 依赖与镜像 | SCA、镜像扫描、secret 扫描 | 报告与处置记录 |
| 动态扫描 | DAST 按项目与暴露面 | 报告；未执行写「未执行」 |
| 渗透测试 | 合规或高风险项目 | 报告与复测 |

测试环境使用脱敏数据；生产测试需明确授权并限制影响。未执行的安全测试不写成「通过」。

本文只管评审与测试组织；具体实现条款归 mv-backend-standards 与 mv-frontend-standards，交付授权归 mv-container-deploy。
