# 应用安全规范

面向 mv 团队自研应用的跨栈安全基线与评审：把安全要求放进设计、编码、构建、交付与运行各阶段。具体框架实现条款留在对应规范，本 skill 只做政策、判据与评审清单。

## 作用与优先级

这是**规范型 Skill**，跨切设计、实现、构建、交付与运维；在威胁建模、安全评审、数据保护、凭据治理、安全测试时引用。优先级：用户明确需求与项目合规要求 → 本规范 → 框架默认。

安全是默认要求，不是上线前补丁。涉及新入口、新数据流、新第三方集成、多租户或高敏数据的变更，先做威胁建模与安全评审，再进入实现。

## 开始前确认

开始前确认：数据敏感级别与合规要求（行业、地域、等保/GDPR 等）、用户角色与外部暴露面、部署环境与信任边界、第三方集成与回调、可接受的风险与整改期限。未确认先问，不默认「内部系统无需安全」。

## 关键规则

1. **威胁建模先行**：新系统、新入口、新数据流先画信任边界，按 STRIDE 或等价清单识别威胁；每条威胁有控制措施或明确的风险接受（责任人、期限）。
2. **默认拒绝与最小权限**：用户、服务、管理端都按最小权限授权；管理面与业务面分离，生产与开发凭据分离；服务间调用也要身份与鉴权，不以网络位置代替。
3. **认证**：团队基线自建 JWT access + refresh，admin/user 会话独立；密码用 BCrypt/Argon2 一类慢散列；登录失败不区分账号与密码；多因素按合规；令牌可吊销、登出即失效。管理员凭据按项目形态两档注入，账号凭据一律不进迁移脚本与代码默认值：无后台的工具端用环境变量承载管理员哈希、内存用户认证，不建用户表；有后台项目的初始管理员由启动期初始化器按环境变量幂等 upsert。毕业判据：出现第二个真实操作者或权限需要分化，即迁正式用户管理与 RBAC 授予。实现见 mv-coding-standards 的 references/java-guide.md「认证与会话」。
4. **授权**：RBAC，权限点在入口层统一校验，前后端共用同一标识；对象级授权每次按资源归属校验（防 IDOR），不信任客户端传入的用户/租户 ID；前端隐藏不代替后端授权。
5. **数据分级**：按公开/内部/敏感/高敏分级；最小采集、展示脱敏、传输与存储加密、日志禁打、按角色授权；留存、删除与测试数据脱敏在方案阶段定。
6. **凭据治理**：凭据不进 Git、镜像、构建上下文、日志与错误信息；按环境隔离；运行时注入或 secrets manager；定期轮换，泄露立即轮换并排查使用记录。
7. **输入与输出**：服务端校验所有外部输入；SQL 参数化；输出按上下文编码；文件上传限制类型/大小/存储位置；评估 SSRF、XXE、反序列化、命令注入；前端 XSS/CSP 细则归 mv-coding-standards。
8. **依赖与供应链**：新依赖过 mv-design-standards 评估；lockfile 锁版本；源码、依赖与镜像扫描进 CI；扫描缺失与漏洞按供应链参考的处置表记录、评估及交接，未执行不算通过。
9. **安全测试**：认证、越权、对象级授权、租户隔离、注入、敏感信息泄露是必测项；SAST/DAST/依赖与镜像扫描按项目执行；渗透测试按合规与风险安排；测试证据如实记录。
10. **日志与审计**：登录、授权失败、敏感操作、管理操作留审计；日志不含密码、令牌与完整敏感数据；审计日志防篡改并按合规留存；时间同步。
11. **失败安全**：认证、授权、校验失败默认拒绝，不降级到宽松路径；异常不泄露堆栈、SQL 与内部地址；登录与关键接口有限流与防爆破。
12. **漏洞响应**：按严重级别定修复窗口；修复后复测；不能按窗口修复的记录补偿控制与复核日期；安全事件按 mv-ops-standards 的事故响应执行，复盘文档格式归 mv-design-standards。
13. **合规边界**：本 skill 只给工程控制；合规结论、数据出境、保留期限由项目与法务确认，不把工程措施写成合规承诺。
14. **评审留痕**：上线前按 [安全评审与安全测试](references/security-review.md) 逐项记录结果、证据、整改与结论；新增入口、数据流或第三方集成时更新威胁模型与数据清单。

## 输出

安全产出：威胁模型与威胁登记表、数据分级清单、安全评审记录（结论、整改项、责任人、期限）、扫描与安全测试证据、未处置风险与接受理由。未执行的检查明确写「未执行」，不虚构通过。

## 边界

认证、会话、RBAC 的具体代码与配置、前端 XSS/CSP、输入渲染与前端密钥边界、测试分层与用例组织归 mv-coding-standards；镜像构建扫描与上传控制、生产部署授权与回滚归 mv-delivery-standards；备份、告警与事故响应流程归 mv-ops-standards；依赖选型与版本升级、系统边界与架构决策归 mv-design-standards。
