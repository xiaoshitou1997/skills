# 业务规则与流程

适用于业务访谈、功能分析与规则评审。业务事实取自当前项目来源；示例只演示描述方法，不作为通用规则。

## 术语与角色

- 术语表只收录容易混淆或影响接口、计算与验收的概念：术语、定义、来源、同义词及字段映射。
- 角色按业务职责定义，区分操作者、审批者、数据所属方与系统身份；同一人可具有多个角色，但权限与数据范围分别确认。
- 未确认的行业缩略语保留原文并标注待确认，不按字面推断其业务含义。

## 业务规则

每条规则写成「前置条件 → 判断 → 结果」，按需求记录适用对象、数据来源、例外与失败行为。规则涉及以下内容时补齐判据：

| 类型 | 必要判据 |
| --- | --- |
| 计算 | 单位、精度、舍入时点、汇总次序、空值与负值行为 |
| 时间 | 业务时区、日历日或工作日、截止边界、超时处理 |
| 权限 | 谁对哪些数据执行何种动作、越权结果、审计需求 |
| 唯一与重复 | 唯一范围、重复请求或重复事件的业务结果 |
| 状态 | 合法迁移、前置状态、触发角色、终态与撤销条件 |
| 外部交互 | 对端责任、超时、重复或乱序消息、人工核对与补偿结果 |
| 数据生命周期 | 来源、修改权、留存依据、归档与删除结果 |

实现机制（锁、事务、消息队列等）由架构与编码规范决定，不在业务规则中提前指定，除非项目已有明确约束。

## 流程与状态

1. 主流程写清触发者、前置条件、步骤、分支与业务完成条件。
2. 补齐相关异常：输入无效、权限不足、外部超时、重复提交、处理中断、人工撤销；无关情形不强加。
3. 有状态对象采用状态表：当前状态、事件、条件、下一状态、副作用、失败后的可观察结果。未定义迁移不自行补为允许。
4. 跨系统流程明确各方完成标准与最终业务结论；是否采用重试、补偿或人工对账由后续设计落实。

## 描述示例

- 场馆预约：「相同资源、相同时间范围的重复申请如何判定冲突」需要确认区间边界和处理中的占用策略，不能套用电商库存规则。
- 检验报告：「报告签发后能否更正」需要确认授权角色、版本保留和已分发副本处理，不能默认允许原记录覆盖。
- 设备告警：「重复上报是否生成新告警」需要确认事件标识、合并窗口与恢复条件；窗口长度由项目确认。

本文件只规定规则的分析与表达；行业口径由业务方确认，技术方案由 mv-architecture-standards 与实现规范承接。
