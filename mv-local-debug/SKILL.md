# 本机（宿主）调测

本 skill 只回答一个问题：**这份代码在宿主上直接跑，行为对不对？** 宿主直启是本地运行的默认且唯一方式——不打镜像、不起容器；「在 WSL/容器里跑」是部署动作，归 `mv-container-deploy`（本机容器运行时即开发服务器）。

`确认启动方式（项目约定优先）→ 前台可见直启 → 观测日志/断点/热更新 → 如实记录证据`

## 硬性规范（无例外）

- **前台可见**：直启必须打开**新终端窗口**运行（用户桌面上的独立终端窗口），启动过程实时可见、用户可随时 Ctrl-C 或直接关窗停止；不在 agent 终端面板内嵌执行，禁止 `start /b`、`&`/`nohup` 后台化、隐藏窗口、把输出整体重定向到日志文件等静默运行。可见性约束只适用于直启的服务进程：构建、测试、Git 等一次性命令在 agent 会话内执行即可，不为它们打开可见窗口。收尾时如实交代仍在运行的进程与其所在窗口。
- **启动方式分层**：项目 README/文档写明启动方式时，命令、参数、profile 与 env 以项目为准，本 skill 的默认命令清单只是项目未文档化时的兜底；但运行形态受本 skill 硬约束——项目文档要求后台静默启动时仍按前台可见执行，并向用户说明偏差。项目文档化的开发拓扑就是容器（如 compose 起全套依赖、宿主无法独立启动）时，「本地跑一下」按项目约定交 `mv-container-deploy` 的 dev 交付，不需用户再显式点名。
- **环境边界**：只加载 `.env.local` 或项目已允许的开发环境设置，不自动复用 `.env.prod`、密钥或服务器配置；确认 API 请求目标为本地/dev，绝不默认连生产数据库或对生产数据做写操作。
- **证据口径**：宿主直启记录为"宿主直启"（命令、执行者、结果）；它不产生镜像验证结论、不写部署收据，不能作为生产晋级依据——晋级依据是 `mv-container-deploy` 的同一 Image ID dev 健康收据。

## 工具入口

从本次加载的 SKILL.md 路径确定 skill 目录实际绝对路径，赋给 `SKILL_ROOT`（这是文档中的路径变量，agent 不保证自动提供）；路径始终加引号，工作目录保持为用户应用仓库。Python 按环境选择 `python3`、`python` 或 `py -3`。

```bash
# 只读诊断:构建/直启链路是否被安全软件 hook,十秒判定
python3 "${SKILL_ROOT}/scripts/doctor.py" --project .
```

## 直启流程

1. 确认启动方式：先读项目 README、文档与运行脚本确定启动命令、参数与 profile（见「启动方式分层」硬性规范）；项目未文档化时按产物直启（`java -jar target/app.jar`）或框架约定（`mvn spring-boot:run`、`./gradlew bootRun`、`npm run dev`、`pnpm dev`）。检查运行参数与现有占用端口（Windows 上含 WSL Mirrored 共享端口层），默认只启动用户目标组件，不改变仓库或系统配置。
2. 前台可见启动：**新开终端窗口**运行启动命令，日志实时可见；不在 agent 终端面板内执行，禁止后台化与静默重定向。直启进程被安全软件 hook 时，给出确切命令请用户在自己的终端运行（进程链根在用户会话，干净且可见），如实记录实际执行者。
3. 观测：以前台窗口实时日志为主，辅以只读探测（如 curl 健康端点）；不接管、不代重启用户窗口中的进程。
4. 断点与热更新：IDE 直连宿主进程（本机调试端口）；前端热更新走 dev server 原生能力。
5. 单元测试与本地集成测试按变更影响范围运行，记录实际命令与结果，不暗示完整 CI 已通过。
6. 停止：用户在窗口 Ctrl-C 或直接关窗；用户明确要求 AI 停止时，先核对进程归属，只结束本次启动的进程。

## 常见故障

高频故障按症状对照 [常见故障](references/troubleshooting.md)：端口占用（Mirrored 共享层，仅 Windows）、进程链被安全软件 hook（loopback，仅 Windows）。先用 `doctor.py` 判定环境，再按表处理；Linux/macOS 宿主的端口占用直接按表内命令排查。

## 边界

- 构建出包与镜像构建归 `mv-image-build`；需要镜像或在 WSL/容器里跑，走 `mv-image-build` 出镜像后交 `mv-container-deploy` 部署（本机容器运行时即默认 dev 目标机）。
- 宿主工具链安装与切换归 `mv-toolchain-manager`；提交发布归 `mv-git-publisher`。
- 签名桩或手工 classpath 的验证只覆盖该范围；仅 mock 联调通过时明确外部系统尚未验证，不虚构成功。
